# LINQ -- GitHub themes

## Open themes
- **Inheritance and polymorphic queries** -- #4585, #4620 show recurring exceptions when entity hierarchies (base/derived classes, interface-based associations) are used. Child-type associations fail (#4585) and unions of interface-implementing types (#4620) block real-world patterns. #5838 adds a related case: InsertWithOutput/UpdateWithOutput on an inheritance-mapped table reads the key as the discriminator. #5837 is the write-side counterpart: derived-entity writes through a base-mapped table fail in the entity builder, Upsert and Merge. 4 open.

- **Eager-load ordering and strategy edge cases** -- #5816, #5904, #5937, #5941 cover the eager-load strategies. Child ordering is not guaranteed under Take/Skip (#5937), OrderBy keys are dropped through Cast/OfType and composite projections (#5941), the keyed strategy silently falls back to Default when a parent reuses an inner window/aggregate value (#5904), and ToSqlQuery over an eager-loaded ITable throws (#5816). Provider-level: Sybase's element-form eager-loading preamble silently drops detail rows (#5865; fix in open PR #5900), and SAP HANA's KeyedQuery detail-side Take/Skip emits a LATERAL correlated to a literal key set (#5940). LoadWith after AsCte is silently ignored (#6276), and an AssociationHelper query-filter DefaultIfEmpty promotion is always overridden (#6144). 8 open issues, 1 open PR.

- **CteUnion eager-load strategy defects** -- #5823 (CteUnion throws on a computed member in the parent projection), #6152 (Union-strategy eager load of a computed detail column throws ArgumentOutOfRangeException in CteContext), #6252 (a nested First()/FirstOrDefault() that finds no row throws "Nullable object must have a value"), #6281 (a nested CteUnion marks the root query as finalized, so the root reaches the database unoptimized), #6292 (an eager-loaded collection joined to an ordered CTE emits the CTE without the join column), #6293 (WithUnionLoadStrategy over a join to an ordered CTE throws "Table not found"), #6294 (a nested db.Select beside or inside an eager-loaded collection fails in CteContext.Register). Open PRs #6282 (skip finalization on CteUnion builds, not on the root) and #6285 (build parent slots from what the parent row reads) address the finalization and slot cases. 7 open issues, 2 open PRs.

- **PreferClientCalculation and missed LEFT JOIN semantics** -- #5925, #5928, #5929, #5985 come from the PreferClientCalculation option (#5604). A missed LEFT JOIN yields default(T) on read but NULL inside SQL calculations (#5929). Bool-returning members route inconsistently (#5925), a declined instance-method translation gets a null receiver (#5928), and a correlated FirstOrDefault references an outer column out of scope (#5985). Same family, newly reported: #6046 (missed LEFT JOIN row calculated over NULL in eager-load and CTE projections), #6087 (math functions over a missed LEFT JOIN row throw "Nullable object must have a value"), #6089 (ClickHouse decimal division by a missed LEFT JOIN row overflows). The read-side fix for projection calculations merged in PR #5983 (2026-10-21), and #5923 and #5932 closed the same day, see Resolved. 7 open issues.

- **Duration and date-difference units** -- #5776 (Contains over a computed duration difference does not reconcile units), #5796 (a set operation mixing a computed difference and a declared duration), #5924 (PreferClientCalculation bypasses the interval unit-declaration guard), #5930 (SQLite: DateTime minus an explicitly declared TimeSpan has no translation). New: #5759 (TimeSpan members and comparisons on native interval columns), #5797 (DateTimeOffset difference measured on the local reading, not the instant; Oracle and SQLite Classic), #5989 (a projected difference of two local DateTime values is read back as TIME; Access fails). Shares the interval-translation work of #5750 (merged 2026-08-21) and open PR #5931 (SQLite date arithmetic with declared durations). Open PRs #5892 (DateTimeOffset difference measured on instants) and #5913 (DateTimeOffset time-zone answers) extend the same date-arithmetic surface. 7 open issues, 3 open PRs, cross-area.

- **Query-build performance and cache keys** -- #5738 (visitor-based tree traversals in query compilation) and #5843 (collection constants in the query-cache key compared by reference) remain open. Cache-key defects: #6059 ([SqlQueryDependent] values that are Equals-equal but render differently share one cache entry), #6045 (CompiledQuery raw SQL format or closure-captured arguments reuse the first build), #6139 (a captured array element evaluated during the build reads a compiled-query argument), #6221 (a compiled query reuses a stale query when a dependent argument is read through a member of a parameter), #6206 (a constant collection that is both a parameter and [SqlQueryDependent] gives stale results), #6225 (a collection mutated in place after the build still matches the cached query), #6235 (queries are reused across mapping schemas whose query filters capture different values), #6231 (a lambda data_type argument to SqlFn misses the cache on every execution), #6297 (root db.Select queries of one result type share one 16-entry bucket). Optimizer side: #6184 (the SQL optimizer consumes build-time values when folding, and they are not recorded in the key) and #5911 (the whole-tree optimizer runs five times per build, SQL-AST). Open PRs #6033 (caches command text for queries with a constant TAKE/SKIP), #6185 (compares build-time values folded out of the SQL) and #6258 (query-cache comparisons of bound expression parameters). 13 open issues, 3 open PRs.

- **Expression translation semantics gaps** -- #5921 (string.Format specifiers silently dropped), #5927 (string.CompareOrdinal mapped onto culture-sensitive CompareTo), #5953 (Sql.Property rejects a name taken from a lambda parameter). Newly reported: #6066 (nullable inline-array Contains converted to string returns NULL where C# returns "False"), #6070 (a narrowing numeric conversion followed by a widening back is dropped before SQL is built), #6072 (integer Sql.Degrees overloads keep the fraction where the engine's DEGREES returns a float), #6079 (inline IN list values typed through SUM and type-changing casts, narrowing a literal the operand does not hold), #6047 (Access: GroupBy(...).Select(aggregate).Contains(value) places the aggregate in WHERE), #6213 (Sql.Property<T> with T different from the member type fails translation; open PR #6268 converts the member access), #6143 ("as Derived" projection throws "Argument types do not match" for a value-type member), #6188 (Sql.AsSql over a conditional of two differently converted columns throws ArgumentException), #6228 (Sum() of a value-converted column compared with a parameter does not convert the parameter), #6219 (a Concat fragment beside a converted column goes through the converter depending on its type), #6298 (comparisons over a cast to an unregistered enum return wrong rows), #6272 (projected enum comparisons fail with SetDefaultFromEnumType, a regression since 6.2.0; open PR #6277 addresses it), #6271 (member alias cannot be resolved after an entity projection), #6154 (nested FromSql converts its arguments under the outer query's mapping schema), #6142 (hand-built SwitchExpression throws NotSupportedException from PathVisitor), #6279 (translation time and memory grow exponentially with a left-deep chain of + in a predicate), #5881 (a chain of 3+ set operations pads members apart when a branch projects a derived type), #6226 (Distinct().Count() returns 1 when the projection contains a client-side method; open PR #6170 falls back to a sub-query for Distinct aggregates that COUNT(DISTINCT) cannot express). Each fails silently, returns a wrong value, or raises an undiagnosed exception instead of a clear translation error. 21 open issues, 3 open PRs.

- **NULL-semantics and wrong-row rewrites** -- #6255 (a nested conditional rewrite returns wrong rows when the branch values are not literals), #6256 (a comparison with a NULL parameter folds to FALSE, so an enclosing NOT returns wrong rows), #6244 (lifted bool? operators over a comparison render invalid SQL on providers without a boolean type), #6209 (ORDER BY over a comparison of a nullable operand sorts unknown rows apart from false), #6165 (grouped or correlated Distinct().Count() drops NULL, translated to COUNT(DISTINCT x)). Adjacent fix: #6120 (negated bool from a nullable comparison drops NULL rows) with PR #6121 merged, see Resolved. 5 open issues.

- **DistinctBy row choice and ordering** -- #6192 (DistinctBy after a limited ordered sequence returns wrong rows on PostgreSQL and DuckDB), #6217 (ConcatenateOrderBy: DistinctBy ranks by the last OrderBy only), #6218 (DistinctBy inside Contains, Delete or RemoveOrderBy is rejected although an OrderBy precedes it), #6223 (DistinctBy after a LEFT JOIN grouped by the inner side's key loses the captured ordering), #6242 (DistinctBy over a GroupBy ordered by a string concatenation overflows the stack on the ROW_NUMBER path), #6245 (DistinctBy over an anonymous-type row fails on the ROW_NUMBER path), #6250 (Distinct() over a client-side computed value deduplicates on the input columns), #6260 (DistinctBy drops an earlier ordering that a later OrderBy reset, which LINQ keeps as tie-breaker), #6284 (DistinctBy ignores an ordered CTE when a correlated collection orders after its filter). Open PR #6197 (DistinctBy row choice after Take/Skip, joins and GroupBy). 9 open issues, 1 open PR.

- **F# query surface** -- #5790 (chained groupJoin with a correlated inner sequence fails to translate) and #5794 (a trailing join after chained groupJoins silently drops unmatched rows). Newly reported: #5886 (F# option .Value comparison passes a non-native element to the provider unconverted). F# option mapping landed in PR #5673 (merged 2026-11-06, see Resolved). 3 open.

- **Query projection optimization** -- #5303 (6.0.0 regression: different result count depending on which properties are projected; epic eager-load). Composite-property selection (#4568) closed 2026-07-22, see Resolved. 1 open.

- **Configuration and data-context APIs** -- #4039, #5195, #5253 span parameter logging (raw vs masked in `.UseDefaultLogging`), context replacement for reusable `IQueryable` pipelines, and LINQPad configuration. Users need more control over data-context lifetime and introspection. 3 open.

- **Version-specific regressions** -- #5560 (DateTime.Date under MSSQL extensions) remains open. #4624 (3.0.0-rc0 + EF Core 3.2.0 null-ref) closed 2026-08-25, see Resolved. 1 open.

- **Provider-specific features** -- #1014 is a voting thread for new RDBMS platforms (cross-area, EXPR-TRANS), #5171 requests ClickHouse tuple support for Oracle-style `IN (tuple)` clauses. Niche but request-backed. 2 open.

- **Schema and infrastructure improvements** -- #5403 (migrate raw SQL in SchemaProvider implementations to LINQ queries), #5455 (support new .NET 11 LINQ APIs). 2 open.

- **Optimistic concurrency & write-back** -- #5650 proposes a `.UseConcurrencyField()` / `.Fetch()` builder pattern for Update operations with optimistic locking and read-back semantics. 1 open (candidate for next-version feature gate).

- **Untranslatable aggregates and correlated subqueries inside projections** -- #5787 (an aggregate with an untranslatable selector inside a projection fails with "There is no method AggregateExecute"), #6035 (ArgumentException "must be reducible node" for a correlated Select(anonymous).Distinct().Count(predicate) inside a projection), #6169 (a correlated aggregate with a client-only predicate throws "must be reducible node"), #6080 (a provider's refusal inside a projection filtered through AsSubQuery() reports only "could not be converted to SQL"), #6034 (apply joins over set operations are not decorrelated). Open PR #5901 (refuse an untranslatable aggregate inside a projection) is the fix candidate. 5 open issues, 1 open PR.

- **Nullable and struct values in projections and set operations** -- #6093 (.Value.member and .HasValue not translated for a nullable struct from an inner projection), #6094 (Union/Concat of a lifted struct with a (T?) null branch throws NullReferenceException on read), #6183 (Union/Intersect/Except return wrong rows for a query-written null test against a (T?)null branch), #6187 (reading a member of an optional object after Union/Intersect with a null branch throws). The struct-constructor and lifted-member fixes (#6069, #6091) merged, see Resolved. 4 open issues.

- **Date/time literal typing, functions and comparisons** -- cross-area. #5997 (date/time literal compared with a coarser column loses its sub-second part), #6081 (SQLite and ClickHouse: a date column IN a list of datetime columns misses a match that equality finds), #6078 (SQL Server: a datetime literal beside MAX/COALESCE of a datetime column is written as datetime2 and misses a read-back value), #6071 (text to date/time casts are wrong on SQLite and Informix and return no rows on YDB). New: #6117 (ClickHouse: a TimeSpan constant is written as whole seconds, dropping its sub-second part), #5961 (three ClickHouse date translations declare a type that contradicts the SQL they emit), #5965 (sub-day date functions over date-only operands fail on SQL Server and Firebird, among others), #5977 (DuckDB: Sql.CurrentTimestamp in a CASE with a TIMESTAMP parameter shifts that parameter), #6147 (Oracle: TIMESTAMP WITH TIME ZONE read as DateTimeOffset is off by one hour during the DST fall-back). The LINQ-side typing of IN lists is #6079, listed under Expression translation semantics gaps. 9 open.

- **netstandard2.0 build does not translate modern BCL overloads** -- #6067 ("Contains" cannot be converted to SQL on .NET 10) and open PR #6074 (recognise C# 14 span Contains in the netstandard2.0 build) are one gap. #6075 (netstandard2.0 build misses string.TrimStart() and TrimEnd() no-arg and char overloads) and open PR #6082 (translate them in the netstandard2.0 build) are another. 2 open issues, 2 open PRs.

- **Remote context serialization and client-side loading** -- new cluster. #6055 (SqlBinaryExpression and SqlUnaryExpression lose their DbDataType in LinqServiceSerializer), #6153 (a remote-context custom scalar with a string converter round-trips through ToString()), #6270 (a UseMappingSchema scope in the remote context does not restore the schema or ConfigurationID), #6167 (remote client on WASM loads ADO.NET assemblies client-side through unguarded provider mapping schemas), #6168 (remote HttpClient client fails when reflection-based System.Text.Json is disabled, WASM and trimmed builds). Open PR #6057 (keep DbDataType of binary and unary expressions in LinqServiceSerializer). 5 open issues, 1 open PR.

- **LEFT JOIN predicate placement** -- new cluster. #6148 (YDB: a LEFT JOIN ON predicate on the outer side only is moved from ON to WHERE, dropping outer rows), #6215 (Access: a LEFT JOIN ON predicate reading only the outer side is applied as a filter), #6216 (Access: IsComplexJoinConditionSupported=false wraps joined-side ON predicates that Jet accepts), #6224 (SQLite: a nullable association with Take(1) and an outer-keyed LEFT JOIN fails with "no such column"). Open PR #6257 keeps outer-dependent LEFT JOIN predicates in ON when complex join conditions are unsupported. 4 open issues, 1 open PR.

## Resolved themes
- **Union and set-operation associations** -- 11+ closed issues (sample: #2503, #2505, #2619, #2932, #2966, #3323, #3346, #3669). Recent closures: #5617 (column order inside UnionAll), #5683 (recursive CTE with differing-but-assignable projection types), #5916 (Concat over IQueryable<object> dropping projection members), #5792 (entity query filter dropping a left-join null check in a set-operation operand), #5976 (Concat/Union with EF Core value converters on DateTime properties throws "operands for operator NotEqual do not match"; closed 2026-10-09), and PR #6060 (regression test for Union over columns sharing a value converter class; merged 2026-10-16). Unions, concats, and set operations with entities, calculated fields, and associations were historically broken; now mostly fixed.

- **Inheritance edge cases** -- 6+ closed (sample: #292, #1008, #1017, #2161, #3034, #5274). Base-class load queries, derived-class filters in LoadWith, discriminator ambiguity, and interface-inheritance mapping have been addressed. Also closed: #5304 (entity inheriting List<T> produced an unreducible SELECT 1 node), #4460 (abstract class in a TPH tree, fixed by PR #5661), #4199 (Property X is not defined for interface type Y; closed 2026-10-21, tests rewritten to the issue's repro and the gate removed in PR #6097), #4773 (casting to interface and SQL generation; closed 2026-10-22), and PR #6109 (associations reached through an interface the base class does not implement; merged 2026-10-22).

- **Calculated fields and projection stability** -- #3150, #2461 were about nested projections losing constants or throwing on union+calculated-field; now resolved. #4568 (selecting all entity columns when only a composite property is selected) closed 2026-07-22 with coverage from PR #5724. #5824 (Update/Delete cannot resolve the target table over a projection that constructs an entity) closed 2026-08-26.

- **Keyed eager-load fixes** -- #5664 (non-deterministic VALUES key order, fixed by PR #5665), #5936 (detail-side Take/Skip applied globally instead of per parent, closed 2026-10-01), and PR #5938 (OrderBy dropped when the ordering key is absent from the projection, closed 2026-10-07).

- **Eager-load fixes, Oct-Nov** -- #6207 (filtered ThenLoad throws "Invalid filter function usage." on a SelectMany/join source; closed, fixed by PR #6220, merged 2026-11-04), #6208 (eager-loading a nullable QueryExpressionMethod association that contains a join dropped parent rows; closed), #6210 (Select(Math.Max(...)).Sum() translation regression in correlated subqueries; closed), and PR #6229 (joins kept inside APPLY subqueries instead of lifted out; merged 2026-11-04; the open follow-up for set operations is #6034).

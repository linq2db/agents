# SQL-PROVIDER

Provider-agnostic SQL emission and statement-level optimization. Lives under `Source/LinqToDB/Internal/SqlProvider/` (the build/optimize machinery -- `LinqToDB.Internal.SqlProvider` namespace) and `Source/LinqToDB/Sql/` (the legacy public `Sql.*` static class -- namespace `LinqToDB`). Together these define the contract between the [SQL-AST](../SQL-AST/INDEX.md) (input) and the per-provider subclasses under `Internal/DataProvider/<Provider>/` (output).

The two anchor abstractions are `ISqlBuilder` (turns a `SqlStatement` into provider-specific SQL text) and `ISqlOptimizer` (rewrites a `SqlStatement` into a shape the builder can emit). Each in-tree provider ships exactly one concrete `<Provider>SqlBuilder : BasicSqlBuilder` and one `<Provider>SqlOptimizer : BasicSqlOptimizer`, registered via `IDataProvider.CreateSqlBuilder` (`Source/LinqToDB/Internal/DataProvider/DataProviderBase.cs:123`). The dialect override mechanism is plain virtual-method inheritance -- `BasicSqlBuilder` exposes ~130 `protected virtual` hooks (sentence prefixes like `BuildXxx`, `IsXxxSupported`, `GetXxxName`) that subclasses override surgically.

`Source/LinqToDB/Sql/` is the user-facing surface: `public static partial class Sql` (`Source/LinqToDB/Sql/Sql.cs:27`) hosts every server-side helper a query can call (`Sql.AsSql`, `Sql.AsNullable`, `Sql.Between`, `Sql.Collate`, `Sql.GroupBy.Rollup`, the `Sql.DateAdd` family, the `Sql.Row(...)` constructors, the `Sql.Window.*` fluent window-function DSL, ...) plus the attribute hierarchy used by user code to declare custom translations (`Sql.ExpressionAttribute`, `Sql.FunctionAttribute`, `Sql.ExtensionAttribute`, `Sql.PropertyAttribute`, `Sql.TableFunctionAttribute`, `Sql.TableExpressionAttribute`, `Sql.QueryExtensionAttribute`).

## Key types

- **`ISqlBuilder`** (`Source/LinqToDB/Internal/SqlProvider/ISqlBuilder.cs:11`) -- the emission contract. Entry point is `BuildSql(commandNumber, statement, sb, optimizationContext, aliases, nullabilityContext, startIndent)` (`ISqlBuilder.cs:15`); auxiliary surface includes `BuildObjectName`, `Convert(sb, value, ConvertType)`, `BuildExpression`, `GetIdentityExpression`, `PrintParameters`, `ApplyQueryHints`, `GetReserveSequenceValuesSql`, `GetMaxValueSql`. ## Interactions

**Inputs.** `BasicSqlBuilder.BuildSql` consumes a finalized `SqlStatement` (see [SQL-AST](../SQL-AST/INDEX.md)) plus an `OptimizationContext`. The statement reaches it after `BasicSqlOptimizer.Finalize` has run.

**Outputs.** A `StringBuilder` of dialect-specific SQL plus `OptimizationContext._actualParameters` (the deduplicated `SqlParameter` list).

**Provider extension points.** Each `<Provider>SqlBuilder` extends `BasicSqlBuilder<TOptions>` and overrides ~5-40 virtuals. Each `<Provider>SqlOptimizer` extends `BasicSqlOptimizer`. For concat, providers override `ConcatStyle` (and optionally `ConcatFunctionName`, `ConcatRequiresExplicitStringCast`). For NULLS ordering, providers set `IsNullsOrderingSupported` and `DefaultNullsOrdering` on `SqlProviderFlags`. For window functions, providers override `GetWindowNullsPlacement`/`WindowFunctionRespectNullsRequired` on the builder and the `Is*Supported` flags on their `WindowFunctionsMemberTranslator` subclass (EXPR-TRANS). For fluent Upsert, providers set `IsInsertOrUpdateWithPredicateSupported`/`IsUpsertWithMergeLoweringSupported`/`IsUpsertMergeWithPredicateSupported`/`IsInsertOrUpdateRequiresAlignedBranches` and optionally override `IsUpsertUpdateWhereAfterSet`.

**`Sql.*` consumption.** `Sql.<method>` calls in user LINQ queries are picked up by [EXPR-TRANS](../EXPR-TRANS/INDEX.md). `Sql.CurrentTimestampUtc` and `Sql.CurrentTzTimestamp` are dispatched through `DateFunctionsTranslatorBase` registration hooks (`DateFunctionsTranslatorBase.cs:63-74`). `Sql.Window.*` fluent calls are dispatched through `WindowFunctionsMemberTranslator` (EXPR-TRANS), which builds the `SqlExtendedFunction` this area's `BasicSqlBuilder` renders.

**Inbound.**
- [LINQ](../LINQ/INDEX.md) -- calls `ISqlOptimizer.Finalize` and `ISqlBuilder.BuildSql` from the query runner.
- [EXPR-TRANS](../EXPR-TRANS/INDEX.md) -- reads `Sql.*` attribute decorations to translate method calls; produces `SqlConcatExpression` via `TranslateBinaryStringConcat`; produces the `SqlExtendedFunction` shape consumed by the window-function emission subsystem (`WindowFunctionsMemberTranslator`).
- All `PROV-*` areas -- every concrete builder/optimizer overrides this area's virtuals.
- [REMOTE-CLIENT](../REMOTE-CLIENT/INDEX.md) -- uses `SqlOptimizerExtensions.PrepareStatementForRemoting`.

**Outbound.**
- [SQL-AST](../SQL-AST/INDEX.md) -- the entire input/output language.
- [MAPPING](../MAPPING/INDEX.md) -- `MappingSchema.GetDbDataType` and `ValueToSqlConverter` are read constantly during emission.
- `Linq.Translation.ISqlExpressionFactory` -- produced by `BasicSqlOptimizer.CreateSqlExpressionFactory`.

## Known issues / debt

Pointers only:

- **`BasicSqlBuilder` is monolithic.** ~5000 lines in one partial type with ~130 virtual hooks (grew from ~4650/~120 with the window-function and Upsert-predicate emission additions this run).
- **`SqlProviderFlags` shape changes are ABI-breaking on the remote channel.**
- **`Sql.EnumAttribute` is undocumented.** XML doc placeholder reads "TODO: write xml doc what it does (I have no idea)".
- **`Sql.Window` was half-implemented as of the prior indexed commit -- resolved this run.** PR #5468 replaced the "Hidden until fully implemented" stub with the full `WindowFunctionBuilder` fluent DSL (~90 extension methods) plus matching `BasicSqlBuilder` emission (NULLS treatment, KEEP, frame EXCLUDE, FROM LAST) and a dedicated capability doc (`WindowFunctions.FeatureMatrix.md`). Remaining gaps are documented there, not here: `MODE() WITHIN GROUP` (non-standard, considered for a future release) and the cosmetic `EXCLUDE NO OTHERS` spelling.
- **Two near-identical date helper files.** `Sql.DateOnly.cs` and `Sql.DateTimeOffset.cs` mirror most of `Sql.DateTime.cs`'s API by data type.
- **`SqlExpressionConvertVisitor` is becoming the catch-all.**
- **`Sql.CurrentTimestampUtc` has no attribute decoration.** Unlike `Sql.CurrentTimestamp` (`[ServerSideOnly]`) and `Sql.CurrentTzTimestamp` (five provider `[Function]`/`[Property]` attributes), `Sql.CurrentTimestampUtc` carries no `[Function]`, `[Property]`, or `[ServerSideOnly]` attribute (`Sql.cs:1184`). Translation depends entirely on `DateFunctionsTranslatorBase.TranslateUtcNow` being overridden by the provider. Providers without that override silently evaluate client-side -- no compile-time or runtime warning. New debt from PR #5467.
- **`Sql.CurrentTzTimestamp` has no mapping for MySQL, SQLite, DB2, Firebird, SAP HANA, Informix, Sybase, Access, SQL CE.** Queries using `Sql.CurrentTzTimestamp` on those providers evaluate client-side without any warning.
- **`ConcatBuildStyle.Plus` is the default `ConcatStyle`** but most modern providers use `Pipes` or `Function`. Providers that do not explicitly override `ConcatStyle` silently emit `+`-style concat. (Deliberate default: the base class cannot assume `||` support.)
- ** ABI additive change.** The two new  fields (, ) are additive but any serialized payload from an older build will deserialize without them (defaults: /).
- ** is  for all providers by default.** Providers that do not set this flag emit CASE emulation sort keys even when ORDER BY direction already matches the natural null placement -- harmless but verbose.
- **`BasicSqlBuilder.BuildInsertOrUpdateQueryAsUpdateInsert` cannot represent an UPDATE-branch predicate at all.** (New this run, PR #5482.) A provider whose native InsertOrUpdate shape is the `IF @@ROWCOUNT = 0`-style emulation throws `LinqToDBException` rather than silently dropping `Upsert(...).Update(v => v.When(...))`'s predicate; callers must go through the 3-query orchestration. Intentional fail-loud, not a bug, but a sharp edge for anyone adding a new such provider.
- **`SqlProviderFlags.IsInsertOrUpdateRequiresAlignedBranches` is SAP-HANA-only today.** Only one provider (SAP HANA) sets it; the flag's contract (fallback to UPDATE-then-INSERT emulation on branch divergence) is exercised by a single case, so a second adopter is the first real test of its generality.
- **Interval lowering capability knobs are defaults-off.** (New, SHA 05150894e.) `CanLowerIntervalDifference` defaults to `false` on `SqlExpressionConvertVisitor`, so every provider must opt in; a provider that does not will see the node reach the builder and be refused by name (`Error_Interval_*`). `BuildSqlInterval*Expression` defaults throw rather than approximate. Sub-tick durations (`DurationUnit.Nanosecond`) have no lowering, and the refusal message names an interval member even when the source was a membership test (`ReconcileDurationUnits`, documented in-code).
- **Window typestate hole.** (New, SHA 05150894e.) `IOThenPartOFrameFinal` inherits `IOFrameFinal`, so `PartitionBy(x).RowsBetweenValues(1, 1)` compiles with no `OrderBy`; tracked as `TODO: v7` in `Sql.Window.cs`. Unordered frames reach the server, where strict providers get a stand-in ordering and the rest sort by nothing.
- **`YDB` window ORDER BY constraint is load-bearing.** (New, SHA 05150894e.) YDB cannot parse a scalar subquery as a window sort key; it works only because YDB requires no ordering anywhere and rejects `RANGE`/`GROUPS` frames at translation. Adding any `IsWindowOrderByRequired` entry for YDB would break it.

# MAPPING -- GitHub themes

## Open themes

- **Type conversion and custom mapping** -- 15 open issues and 2 open PRs. Users struggle with custom value converters and generic types: open generic converters (#1994), provider-specific conversions for stored procedure outputs (#2103), ValueToSqlConverter for generic types (#3117), and MapValue read/write asymmetry for undefined values (#363). F# option element converters are not applied to `.Value` comparisons, so a non-native element reaches the provider unconverted (#5886). Mapping schema defaults are keyed by CLR type only, while some defaults need the database type too: the "value read for NULL" default (#5999, e.g. SQL Server datetime cannot hold 0001-01-01) and attribute-built SQL typed with the schema default for the member's CLR type instead of the value's type (#6044, ClickHouse DateTime64 coercion skipped). A provider reader is missing for a type the provider returns: SQLite.MS reads DateTimeOffset through GetDateTime and loses the offset (#6031). Converted columns are compared, concatenated and summed inconsistently: a concat fragment beside a converted column goes through the converter or not depending on the fragment's type (#6219), `Sum()` of a value-converted column compared with a parameter does not convert the parameter (#6228), `Sql.AsSql` over a conditional of two differently converted columns throws (#6188), and a value compared with `Sql.Convert(NVarChar)` over a converted VarChar column loses non-Latin text on SQL Server (#6247). A custom scalar type with a string converter does not round-trip through ToString() in the remote context (#6153). Projected enum comparisons regressed in 6.2.0 under SetDefaultFromEnumType (#6272; open PR #6277 targets it). EF Core with Npgsql UseNodaTime cannot read a value-converted DateTime column (Instant to DateTime, #5981). Open PR #5931 targets SQLite DateTimeOffset arithmetic and invariant parameters. Sample: #363, #1994, #2103, #3117, #5886, #5981, #5999, #6031, #6044, #6153, #6188, #6219, #6228, #6247, #6272, #5931 (PR), #6277 (PR).

- **Fluent mapping API and attribute refactoring** -- 7 open issues and 1 open PR. Requests for a consistent fluent mapping API and for decoupling attributes from metadata. Open items: refactoring fluent builders away from column/table attribute logic (#3914), decoupling model attributes from metadata (#2502), QueryFilter declarative syntax (#4543), type references in AssociationAttribute.QueryExpressionMethod (#4273), System TableAttribute forcing Column attributes (#3691), metadata readers unable to see the active MappingSchema (#5675), and whether extension and table-function attribute lookups follow a table handle's MappingSchema (#6269, updated 2026-11-08). Open PR #6151 removes MapMember shadows of translators and attributes and adds analyzer rules LINQ2DB0007-0009. Recent closure: #5540 (ExpressionMethod substitution at materialization, v6 regression) closed 2026-07-09. Sample: #3914, #2502, #4543, #4273, #3691, #5675, #6269, #6151 (PR).

- **Association and relationship mapping** -- 5 open issues. Problems with association key resolution and EF compatibility (owned entities, FK-PK matching in complex scenarios). Newer reports: the query-filter DefaultIfEmpty promotion in AssociationHelper (lines 172-180) is always overridden (#6144); a nullable association with Take(1) and an outer-keyed LEFT JOIN fails on SQLite with "no such column" (#6224); Delete() over a projected optional association deletes from the root table (#6239). Sample: #4627, #4650, #6144, #6224, #6239.

- **Advanced mapping scenarios** -- 9 open issues and 1 open PR. Emerging pattern: need for more flexible property-column mapping, for both inheritance and derived types. Open items: dynamic tables (#4730), with open PR #6110 proposing a runtime column set in a projection (SelectDynamic); complex type property built from multiple columns with fluent mapping (#4758), explicit interface implementation (#4715), chunked BLOB reads (#1075), derived-entity writes through a base-mapped table in entity-builder, Upsert and Merge (#5837, updated 2026-11-09), a [Column] on a new-shadowing member of a TPH subtype silently ignored (#5852, filed 2026-09-02), InsertWithOutput/UpdateWithOutput on an inheritance-mapped table reading the key as the discriminator (#5838), an `as Derived` projection throwing for a value-type member (#6143), and a design proposal for a stable write-side extension model (soft delete, audit stamps, tenant-scoped writes; #6150). Sample: #4730, #4758, #4715, #1075, #5837, #5852, #5838, #6143, #6150, #6110 (PR).

- **Infrastructure, caching and provider data types** -- 14 open issues and 4 open PRs. Long-standing refactoring requests to unify provider-specific type systems and add naming convention support (snake_case, CamelCase), plus mapping cache growth. Items: unify provider data types (#1181), NamingConventions (#4700), MappingAttributesCache unbounded growth (#5692), EntityDescriptorsCache pinning discarded schemas (#5718), ulong.MaxValue literal failing on several providers with a direct vs remote difference on PostgreSQL (#5973), a decimal mapped with Precision but no Scale written through a Decimal(P, 0) parameter on YDB (#6063), and SQLite.Classic with DateTimeOffset as a primary key (#3766). Mapping schema scope is leaking across contexts: the query cache reuses queries across mapping schemas whose query filters capture different values (#6235); a nested FromSql converts its arguments under the outer query's mapping schema (#6154); build steps must use the source sequence's MappingSchema (#5951, open PR #6145 adds LINQ2DB0010); a remote UseMappingSchema scope does not restore the schema or ConfigurationID (#6270). Provider schema selection and loading: PostgreSQL 11/12/13 providers use the 9.5 mapping schema (#6137); unguarded provider mapping schemas load ADO.NET assemblies client-side in the WASM remote client (#6167). The remote serializer loses DbDataType on binary and unary expressions (#6055; open PR #6057). Related open PRs: #5694 bounds MappingAttributesCache growth (fixes #5692) and #4836 replaces the SqlDataType AST type in the mapping schema with DbDataType. Sample: #1181, #4700, #5692, #5718, #5973, #6063, #6235, #6270, #6137, #6055, #5694 (PR), #4836 (PR), #6145 (PR), #6057 (PR).

- **netstandard2.0 build loses provider type conversions** -- 2 open issues. Provider type conversions gated by TFM symbols (SUPPORTS_DATEONLY, #if) are not compiled into the netstandard2.0 asset, so an app on a modern runtime that loads that asset cannot read DuckDB TIMETZ into TimeSpan (#6084) or MySQL VECTOR into float[] with MySqlConnector (#6085). The PostgreSQL case (#6077, Npgsql 10 date/time into DateTime/TimeSpan/NpgsqlRange<DateTime>) was fixed by PR #6092, closed and merged 2026-11-10, and is listed under Resolved. Sample: #6084, #6085.

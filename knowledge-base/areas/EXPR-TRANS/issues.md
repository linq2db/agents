# EXPR-TRANS -- GitHub themes

## Open themes

- **Member/Method translation refactoring** -- Migration of expression methods from the legacy `Sql.Extension` + expose-mapping system into the member-translator pipeline. Landed earlier: #5613 (string.CompareTo, merged 2026-06-14), #5544 (string.IsNullOrWhiteSpace, merged 2026-06-09), #5577 (expand member/method mappings at expose, merged 2026-06-07). Still open: #5716 -- `IMemberTranslator` public surface is unusable without `LinqToDB.Internal.*` types (open since 2026-07-13). #5541 (ExpressionMethodAttribute.IsColumn=false at materialization) is closed without a merge record in the index. New since 2026-10-10: #6044 -- SQL built from `Sql.Ext` / `[Sql.Expression]` / `[Sql.Function]` is typed with the mapping schema's default for the CLR return type, not the value's type; on ClickHouse an analytic `MAX` over a whole-second `DateTime` is reported as `DateTime64(7)` and the server refuses the query. #5953 -- a `Sql.Property` name computed from a lambda parameter fails with an undiagnosed `InvalidOperationException`. #6072 -- integer `Sql.Degrees` overloads keep the fraction where the engine's `DEGREES` returns a float (SQLite, DuckDB). #6041 -- YDB `Math.Floor` / `Ceiling` / `Truncate` over `decimal` are computed through `Double` and lose digits. PR #5943 (open, YDB) widens the scaled intermediate in `ROUND` emulation.
- **Projection computation & client-side evaluation** -- #5604 (PreferClientCalculation option, merged 2026-06-26) keeps projection computations client-side, restoring v5 behavior for computed columns. Follow-up #5926 (honour it for string interpolation via declarable optional translation) is closed without a merge record. Open: #5901 (refuse an untranslatable aggregate inside a projection, draft PR fixing #5787). #5787 (open issue) reports the same aggregate failure as "There is no method 'AggregateExecute'" after the query has already run on the server. #6080 (open) -- a provider's refusal inside a projection filtered through `AsSubQuery()` reports only "could not be converted to SQL"; the provider's reason is dropped. #6035 (open) -- a correlated `Select(anonymous).Distinct().Count(predicate)` in a projection fails with "must be reducible node": an unresolved `ContextRefExpression` reaches the result-mapper compile.
- **Missed LEFT JOIN row values in projections** -- With `PreferClientCalculation` off, a projection calculation over a NOT NULL column of a missed LEFT JOIN row was computed over SQL NULL, while C# reads `default(T)`. Fixed for the calculation path by #5983 (see Resolved). Same family still open: #6046 (eager-load and CTE projections, option off), #6087 (math functions over the missed row throw "Nullable object must have a value", option on), #6089 (ClickHouse: decimal division by a missed row raises "Decimal convert overflow"), #6088 (Sybase: `new DateTime(...)` / `Sql.MakeDateTime` over NULL parts raises instead of answering NULL).
- **Lateral / APPLY join emulation** -- #5396 (emulate Lateral/Apply join for SQLite and other providers, open issue) and #5397 (lateral join emulation, open PR). The same gap blocks correlated projections on providers without native APPLY. #6034 (open, new) -- an apply join whose source is a set operation is never decorrelated, so it always needs `LATERAL` / `APPLY`, even when each branch is correlated by a plain equality that could move into the join condition.
- **Expression/query cache correctness** -- Open: #6059 (`[SqlQueryDependent]` values that are `Equals`-equal but render differently share one cache entry: decimal scale, one instant at two `DateTimeOffset` offsets, `DateTime` values differing only in `Kind`) and #6045 (a compiled query reuses its first build when a raw SQL format or argument captured from the closure changes; later calls run the first SQL or throw `InvalidCastException`). The FromSql / Sql.Expr cache defects #6000 and #5857 are fixed (see Resolved). #5769 (expression caching with Sql.IExtensionCallBuilder) closed 2026-09-03.
- **Nullable equality, IN and Contains semantics** -- Places where a C# `==`, `Contains` or inline `IN` gives a different answer in SQL: #6065 (DB2: a nullable equality ORed with another condition evaluates to UNKNOWN when compared as a value), #6066 (a nullable inline-array `Contains` converted to a string returns NULL where C# returns "False"), #6079 (inline IN values typed through `SUM` and type-changing casts, narrowing a literal), #6064 (an IN list beside a decimal aggregate writes captured values at the schema's default scale; ClickHouse, YDB), #6081 (SQLite, ClickHouse: a date column IN a list of datetime columns misses a match that `==` finds), #6047 (Access: `GroupBy(...).Select(g => aggregate).Contains(x)` puts the aggregate in WHERE).
- **netstandard2.0 asset keeps modern-overload translation** -- The ns2.0 build recognises only the overloads a net8+ `#if` covers, so a modern runtime loading that asset refuses source that also compiles on net462 (see AGENTS.md on TFM gates). #6067 (open, needs-tests: `Contains` on a temp-table filter cannot be converted on .NET 10), PR #6074 (open draft, recognises the C# 14 span `Contains`, fixes #6067), #6075 (open: `TrimStart()` / `TrimEnd()` no-arg and char overloads not translated), PR #6082 (open draft, fixes #6075).
- **Members of lifted or upcast values built in an inner projection** -- A struct built in an inner projection, as `(T?)new T(...)` or `(IFace)new Impl(...)`, is read by an outer query. #6090 (open: "Property is not defined for type Nullable<T>" when read), PR #6091 (open, fixes #6090: `CorrectTrackingPath` builds member access on the constructed type), #6093 (open: `.Value.<member>` and `.HasValue` on the lifted struct are not translated), #6094 (open: a union of a lifted struct with a `(T?)null` branch builds no marker column and throws `NullReferenceException` on read), #6068 (open: a struct referenced twice fails with "Coalesce used with type that cannot be null"), PR #6069 (open, fixes #6068). #4773 (open: casting to an interface plus an association fails during SQL generation) is the same family.
- **Typed binary/unary expressions lose DbDataType** -- A node built with an explicit `DbDataType` (e.g. `Decimal(10,2)`) loses it on rebuild or serialization, so the mapping-schema default is used and a narrowing cast can be folded away. #6055 (open, remote: `LinqServiceSerializer` writes only the CLR type of `SqlBinaryExpression` / `SqlUnaryExpression`), #6056 (open: a Transform-mode visitor rebuilds the node with the CLR type only), PR #6057 (open draft, fixes #6055).
- **Narrowing numeric and text/date casts** -- #6070 (open: a C# `(int)x` over a `double`, followed by a conversion back or a comparison with a value of the operand's type, is dropped before SQL is built, so the query computes with the untruncated value). #6071 (open: text to date/time casts are wrong on SQLite and Informix and return no rows on YDB; the fold of the `DateTime.Parse` round trip hid these paths for the one shape the corpus exercises). #5997 (open: a date/time literal compared with a coarser date/time column is narrowed and loses its sub-second part; ClickHouse).
- **Date/time translation follow-ups** -- Open PRs on date/time lowering: #5913 (open draft, time-zone read for `DateTimeOffset` and offset-aware composition, EF Core `AtTimeZone` parity), #5892 (open draft, fixes #5797 and #3766: a `DateTimeOffset` difference is measured on instants, not local readings; Oracle and SQLite Classic), #5931 (open, fixes #5930: SQLite `DateTimeOffset` arithmetic keeps the offset), #5959 (open, fixes #5955 and #5960: ClickHouse date operands are coerced to `DateTime64` before the epoch functions, a regression from #5750).
- **Correlated column subquery results** -- #6032 (open, Access: an uncorrelated `TOP 1 ... ORDER BY` column subquery whose own select list is a correlated scalar subquery returns per-row wrong values on ACE OLE DB and ODBC, silently).

## Resolved themes

- **String method translation consolidation** -- #5613 (string.CompareTo), #5544 (string.IsNullOrWhiteSpace), #5504 (string.Concat across all providers, merged 2026-05-15) -- moved from legacy `Sql.Extension` into the member-translator pipeline with per-provider overrides.
- **Expression optimization post-AST refactor** -- #5570 (collapse nested case-conversion wraps in Guid-to-string translation), #5567 (restore IS NULL pushdown through SqlConcatExpression), #5566 (skip bogus IS NULL guards on non-null Sybase concat operands), #5569 (Sybase concatenation to ANSI ||), #5602 (MA0006/MA0154 fixes for #5570). All post-#5504 string-concat AST refactor.
- **Correlated subquery detection & validation** -- #5574 (reject unsupported correlated subqueries in expression position on ClickHouse/YDB), #5558 (fix InvalidCastException in APPLY-to-JOIN conversion with correlated Contains). #6024 (closed 2026-10-12: the Oracle 11 query validator rejected IS NOT NULL on a column subquery's own table as a parent reference; fixed by PR #6027, merged 2026-10-12).
- **Nullable type handling in subqueries & correlated contexts** -- #5586 (Nullable<T>.HasValue over unbound members, merged 2026-06-19), #5582 (null-safe IN/NOT IN emulation, merged 2026-06-04).
- **Type translation & casting** -- #5605 (SqlServer decimal overflow fallback via SqlDecimal, merged 2026-07-11), #5466 (DateTimeOffset.DateTime as cast, merged 2026-06-05), #5581 (nullable DateTime subtraction, merged 2026-06-12).
- **TimeSpan & date-difference translation** -- #5750 (TimeSpan members and date differences as elapsed time, merged 2026-08-21), #5739 (native TimeSpan translation, closed), #3994 (original TimeSpan WIP, closed; its binary/unary fixes were carried by #5212).
- **Binary/unary operator translation** -- #5212 (merge binary/unary translation fixes from #3994), closed 2026-08-19 without a merge record in the index.
- **Window Functions API** -- #5468 (new Sql.Window fluent API, merged 2026-07-03) replaces the older `Sql.Ext().Over().ToValue()` pattern. #5725 (fold boolean expressions used in window clauses and arguments, merged 2026-09-05).
- **Projection & materialization edge cases** -- #5587 (spurious [item] column on local-collection LEFT JOIN with decimal projection), #5577 (expand member/method mappings during initial expose), #5581 (nullable DateTime subtraction in final projection), #5818 (set-operation projection rejecting an untranslatable concat operand, merged 2026-08-30).
- **Missed LEFT JOIN calculation** -- #5932 and #5923 (both closed 2026-10-21): a non-nullable member of a missed LEFT JOIN row was read as `default(T)` but calculated over NULL in SQL, and `Sql.ToNullable` over a binary expression returned a value instead of NULL under `PreferClientCalculation`. Fixed by #5983 (merged 2026-10-21): projection calculations read such a column as `COALESCE(col, default(T))`.
- **FromSql / Sql.Expr query cache** -- #6000 (closed 2026-10-16; query cache reused stale SQL when `FromSqlScalar` was nested in an `IN`) and #5857 (closed 2026-10-16; the registered `FormattableString` was compared by reference, so the query was rebuilt on every execution). Fixed by PR #6003 (merged 2026-10-16). PR #6007 (merged 2026-10-13) stops `ConvertToExists` from editing the cached statement, and PR #6008 (merged 2026-10-19) replaces raw SQL arguments the format never references with NULL. #5769 (closed 2026-09-03) is the earlier expression-caching case.
- **Set-operation operand comparison & value converters** -- #5976 (closed 2026-10-09, no merge record: Concat and Union raised "operands for operator NotEqual do not match" with EF Core value converters). #6052 (closed 2026-10-16: Union over columns sharing a value converter class threw "Argument types do not match"; the defect was fixed in 6.5.1 by #5978, and PR #6060 (merged 2026-10-16) adds the regression test for that shape).
- **Interface-typed property access** -- #4199 (closed 2026-10-21): "Property X is not defined for interface type Y" after a Select casts to a concrete type. Fixed in 6.0.0-preview.1 by #3401; the test was rewritten to the issue repro by PR #6097 (merged 2026-10-21) and its gate removed.

# EXPR-TRANS -- GitHub themes

## Open themes
- **Member/Method translation refactoring** -- Migration of expression methods from the legacy `Sql.Extension` + expose-mapping system into the member-translator pipeline. Landed earlier: #5613 (string.CompareTo, merged 2026-06-14), #5544 (string.IsNullOrWhiteSpace, merged 2026-06-09), #5577 (expand member/method mappings at expose, merged 2026-06-07). Still open: #5716 -- `IMemberTranslator` public surface is unusable without `LinqToDB.Internal.*` types (open since 2026-07-13). #5922 -- MapMember entries shadow member-translator registrations; PR #6151 (open) removes the shadows and adds LINQ2DB0007-0009. #5541 (ExpressionMethodAttribute.IsColumn=false at materialization) is closed without a merge record in the index. #6213 -- `Sql.Property<T>` with T different from the member type fails translation; PR #6268 (open) converts the member access to T. #6188 -- `Sql.AsSql` over a conditional of two differently converted columns throws ArgumentException instead of refusing. #6044 -- SQL built from `Sql.Ext` / `[Sql.Expression]` / `[Sql.Function]` is typed with the mapping schema's default for the CLR return type, not the value's type; on ClickHouse an analytic `MAX` over a whole-second `DateTime` is reported as `DateTime64(7)` and the server refuses the query. #5953 -- a `Sql.Property` name computed from a lambda parameter fails with an undiagnosed `InvalidOperationException`. #6072 -- integer `Sql.Degrees` overloads keep the fraction where the engine's `DEGREES` returns a float (SQLite, DuckDB). #6041 -- YDB `Math.Floor` / `Ceiling` / `Truncate` over `decimal` are computed through `Double` and lose digits. #5927 -- `string.CompareOrdinal` and ordinal `string.Compare` map onto the culture-sensitive `CompareTo` translation. #5921 -- `string.Format` / interpolated string format specifiers are silently dropped from the generated SQL.
- **Projection computation & client-side evaluation** -- #5604 (PreferClientCalculation option, merged 2026-06-26) keeps projection computations client-side, restoring v5 behavior for computed columns. Follow-up #5926 (honour it for string interpolation via declarable optional translation) is closed without a merge record. Open: #5901 (open PR refusing an untranslatable aggregate inside a projection, fixes #5787). #5787 (open issue) reports the same aggregate failure as "There is no method 'AggregateExecute'" after the query has already run on the server. #6080 (open) -- a provider's refusal inside a projection filtered through `AsSubQuery()` reports only "could not be converted to SQL"; the provider's reason is dropped. #6035 (open) -- a correlated `Select(anonymous).Distinct().Count(predicate)` in a projection fails with "must be reducible node": an unresolved `ContextRefExpression` reaches the result-mapper compile. #5928 (open) -- under PreferClientCalculation a declined instance-method translation gets a null receiver. #5925 (open) -- bool-returning members in a projection are routed inconsistently. #5924 (open) -- PreferClientCalculation bypasses the interval unit-declaration guard.
- **Missed LEFT JOIN row values in projections** -- With `PreferClientCalculation` off, a projection calculation over a NOT NULL column of a missed LEFT JOIN row was computed over SQL NULL, while C# reads `default(T)`. Fixed for the calculation path by #5983 (see Resolved). Same family still open: #6046 (eager-load and CTE projections, option off), #6087 (math functions over the missed row throw "Nullable object must have a value", option on), #6089 (ClickHouse: decimal division by a missed row raises "Decimal convert overflow"), #6088 (Sybase: `new DateTime(...)` / `Sql.MakeDateTime` over NULL parts raises instead of answering NULL), #5929 (open: under PreferClientCalculation a missed LeftJoin computes on `default(T)` instead of NULL).
- **Lateral / APPLY join emulation** -- #5396 (emulate Lateral/Apply join for SQLite and other providers, open issue) and #5397 (lateral join emulation, open PR). The same gap blocks correlated projections on providers without native APPLY. #6034 (open) -- an apply join whose source is a set operation is never decorrelated, so it always needs `LATERAL` / `APPLY`, even when each branch is correlated by a plain equality that could move into the join condition. #5940 (open, SAP HANA) -- KeyedQuery detail-side Take/Skip emits a LATERAL correlated to a literal key set.
- **Expression/query cache correctness** -- Open: #6059 (`[SqlQueryDependent]` values that are `Equals`-equal but render differently share one cache entry: decimal scale, one instant at two `DateTimeOffset` offsets, `DateTime` values differing only in `Kind`) and #6045 (a compiled query reuses its first build when a raw SQL format or argument captured from the closure changes; later calls run the first SQL or throw `InvalidCastException`). #6221 (a compiled query reuses a stale query when a dependent argument is read through a member of a parameter), #6139 (a captured array element evaluated during the build reads a compiled-query argument instead), #6206 (a constant collection that is both a parameter and a `[SqlQueryDependent]` argument gives stale results), #6225 (a collection mutated in place after the build still matches the cached query), #6235 (queries are shared across mapping schemas whose query filters capture different values), #6231 (a lambda data_type argument of `SqlFn` misses the cache on every execution), #5843 (collection constants in the key are compared by reference), #6297 (root `db.Select` queries of one result type share one 16-entry bucket), #6184 (record which build-time values the SQL optimizer consumes when folding; open PR #6185 compares them). Open PR #6258 fixes query-cache comparisons of bound expression parameters. The FromSql / Sql.Expr cache defects #6000 and #5857 are fixed (see Resolved). #5769 (expression caching with Sql.IExtensionCallBuilder) closed 2026-09-03.
- **Nullable equality, IN, Contains and NULL semantics** -- Places where a C# `==`, `Contains` or inline `IN` gives a different answer in SQL: #6065 (DB2: a nullable equality ORed with another condition evaluates to UNKNOWN when compared as a value), #6066 (a nullable inline-array `Contains` converted to a string returns NULL where C# returns "False"), #6079 (inline IN values typed through `SUM` and type-changing casts, narrowing a literal), #6081 (SQLite, ClickHouse: a date column IN a list of datetime columns misses a match that `==` finds), #6047 (Access: `GroupBy(...).Select(g => aggregate).Contains(x)` puts the aggregate in WHERE). #6209 (ORDER BY over a comparison of a nullable operand sorts unknown rows apart from false). #6244 (lifted `bool?` logical AND / OR over a comparison renders invalid SQL on providers without a boolean type).
- **netstandard2.0 asset keeps modern-overload translation** -- The ns2.0 build recognises only the overloads a net8+ `#if` covers, so a modern runtime loading that asset refuses source that also compiles on net462 (see AGENTS.md on TFM gates). #6067 (open, needs-tests: `Contains` on a temp-table filter cannot be converted on .NET 10), PR #6074 (open, recognises the C# 14 span `Contains`, fixes #6067), #6075 (open: `TrimStart()` / `TrimEnd()` no-arg and char overloads not translated), PR #6082 (open, fixes #6075).
- **Members of lifted or upcast values built in an inner projection** -- A struct built in an inner projection, as `(T?)new T(...)` or `(IFace)new Impl(...)`, is read by an outer query. #6093 (open: `.Value.<member>` and `.HasValue` on the lifted struct are not translated), #6094 (open: a union of a lifted struct with a `(T?)null` branch builds no marker column and throws `NullReferenceException` on read), #6271 (open: a member alias cannot be resolved after an entity projection), #6143 (open: an `as Derived` projection throws "Argument types do not match" for a value-type member). #4773 (casting to an interface plus an association fails during SQL generation) is the same family and is closed (see Resolved).
- **Typed binary/unary expressions lose DbDataType** -- A node built with an explicit `DbDataType` (e.g. `Decimal(10,2)`) loses it on rebuild or serialization, so the mapping-schema default is used and a narrowing cast can be folded away. #6055 (open, remote: `LinqServiceSerializer` writes only the CLR type of `SqlBinaryExpression` / `SqlUnaryExpression`), #6056 (open: a Transform-mode visitor rebuilds the node with the CLR type only), PR #6057 (open, fixes #6055).
- **Narrowing, enum and text/date casts** -- #6070 (open: a C# `(int)x` over a `double`, followed by a conversion back or a comparison with a value of the operand's type, is dropped before SQL is built, so the query computes with the untruncated value). #6071 (open: text to date/time casts are wrong on SQLite and Informix and return no rows on YDB; the fold of the `DateTime.Parse` round trip hid these paths for the one shape the corpus exercises). #5997 (open: a date/time literal compared with a coarser date/time column is narrowed and loses its sub-second part; ClickHouse). #6298 (open: comparisons over a cast to an unregistered enum return wrong rows). PR #6277 (open, fixes comparisons over a projected enum cast with `SetDefaultFromEnumType`).
- **Date/time translation follow-ups** -- Open PRs on date/time lowering: #5913 (open draft, time-zone read for `DateTimeOffset` and offset-aware composition, EF Core `AtTimeZone` parity), #5892 (open draft, fixes #5797 and #3766: a `DateTimeOffset` difference is measured on instants, not local readings; Oracle and SQLite Classic), #5931 (open, fixes #5930: SQLite `DateTimeOffset` arithmetic keeps the offset). Open issue behind them: #5797 (DateTimeOffset difference measured on the local reading). Also open: #5961 (ClickHouse: three date translations declare a type that contradicts the SQL they emit), #5977 (DuckDB: `Sql.CurrentTimestamp` in a CASE with a TIMESTAMP parameter shifts the parameter by the local UTC offset), #6147 (Oracle: `TIMESTAMP WITH TIME ZONE` read as `DateTimeOffset` is off by one hour in the DST fall-back hour), #5989 (a projected difference of two local DateTime values is read back as TIME: Access fails, DB2 and Firebird truncate it), #5776 (`Contains` over a computed duration difference does not reconcile units), #5796 (open: a set operation cannot carry a computed difference and a declared duration in one position), #5759 (TimeSpan members and comparisons on native interval columns), #6117 (ClickHouse: a TimeSpan constant is written as whole seconds, dropping its sub-second part).
- **Correlated column subquery results** -- #6032 (open, Access: an uncorrelated `TOP 1 ... ORDER BY` column subquery whose own select list is a correlated scalar subquery returns per-row wrong values on ACE OLE DB and ODBC, silently). #6169 (open: a correlated aggregate with a client-only predicate throws "must be reducible node"). #6234 (open: a correlated GroupBy keyed on an outer-row member emits the outer column in GROUP BY). #6175 (open, Oracle 12: a grouped aggregate over a correlated derived table returns uncorrelated results). #6166 (open, Sybase: a correlated derived table under an aggregate reaches ASE instead of being refused).
- **Eager-load CTE union strategy** -- CteUnion builds that fail or finalize the root query too early. Open issues: #5823 (EagerLoadingStrategy.CteUnion throws on a computed member in the parent projection), #6152 (union-strategy eager load of a computed detail column throws ArgumentOutOfRangeException in CteContext.RegisterField), #6294 (a nested db.Select beside or inside an eager-loaded collection fails in CteContext.RegisterField), #6281 (a nested CteUnion marks the root query as finalized, so the root reaches the database unoptimized), #6252 (open: a nested First()/FirstOrDefault() that finds no row throws "Nullable object must have a value"), #6292 (open: an eager-loaded collection joined to an ordered CTE emits the CTE without the join column), #6293 (open: WithUnionLoadStrategy over a join to an ordered CTE throws "Table not found"). Open PRs: #6282 (skip finalization on the query CteUnion builds, not on the root), #6285 (build the CteUnion parent slots from what the parent row reads).
- **Eager-load strategy and ordering** -- #5904 (keyed eager-load strategy silently falls back to Default when a parent reuses an inner window/aggregate value), #5941 (remap the OrderBy key through Cast/OfType and through composite projections instead of dropping it), #5937 (open: eager-loaded child ordering is not guaranteed when the child sequence is limited with Take/Skip), #6276 (open: `LoadWith` after `AsCte` is silently ignored).
- **Expression-tree node coverage in visitors** -- Node types the visitors do not handle. #6142 (open: a hand-built SwitchExpression in a query tree throws NotSupportedException from PathVisitor), #6138 (open: Expose leaves both branches of a client-evaluable conditional unvisited when its test turns into a subquery), #5738 (open: audit and optimize visitor-based tree traversals in query compilation). Same family, closed: #5879 (see Resolved).
- **DistinctBy and Distinct().Count() translation** -- Open issues: #6217 (ConcatenateOrderBy: DistinctBy ranks by the last OrderBy only, not the concatenated ordering), #6218 (DistinctBy inside Contains, Delete or RemoveOrderBy is rejected although an OrderBy precedes it), #6242 (DistinctBy over a GroupBy ordered by a string concatenation overflows the stack on the ROW_NUMBER path), #6284 (DistinctBy ignores an ordered CTE when a correlated collection orders after its filter), #6223 (DistinctBy after a LEFT JOIN grouped by the inner side's key loses the captured ordering), #6245 (open: DistinctBy over an anonymous-type row fails on the ROW_NUMBER path), #6260 (open: DistinctBy drops an earlier ordering that a later OrderBy reset), #6250 (open: Distinct() over a client-side computed value deduplicates on the input columns), #6165 (grouped or correlated Distinct().Count() drops NULL: translated to COUNT(DISTINCT x)), #6226 (Distinct().Count() returns 1 when the projection contains a client-side method). Open PRs: #6197 (fix DistinctBy row choice after Take/Skip, joins and GroupBy), #6170 (fall back to a sub-query for Distinct aggregates that COUNT(DISTINCT) cannot express). The correlated Distinct().Count(predicate) case #6035 is in the projection theme.
- **Set operations with nullable and lifted branches** -- #6183 (open: Union/Intersect/Except return wrong rows for a query-written null test against a `(T?)null` branch), #5881 (open: a chain of 3+ set operations pads members apart when a branch projects a derived type), #6187 (open: reading a member of an optional object after Union/Intersect with a null branch throws). The lifted-struct union case #6094 is in the lifted-members theme.
- **String concatenation and conversion lowering** -- #6219 (open: a concat fragment beside a converted column goes through the column converter depending on its type), #6193 (open, Access: concatenating a column with a non-null string parameter overflows the stack in SqlExpressionConvertVisitor), #6195 (open, DB2: the same concatenation fails with CLI0109E because COALESCE over the parameter and an empty string types the marker as VARCHAR(0)), #6212 (open, SQL Server: string concatenation with a parameter is cut at 4000 characters), #6238 (open, SQL Server: PadRight / Sql.PadLeft over 4000 characters are cut at 4000), #6247 (open, SQL Server: a value compared with `Sql.Convert(NVarChar)` over a converted VarChar column loses non-Latin characters), #6237 (open, DB2: `Sql.Convert(Sql.Types.NVarChar(n), column)` renders a blank-padded Char), #6200 (open, PostgreSQL: `string.Join` over object items types CONCAT_WS as its first item, so a non-string first item fails to materialize), #6262 (open, YDB: `Sql.Substring` / `Sql.Left` with a NULL length return the rest of the string instead of NULL).
- **Math.Round and rounding translation across providers** -- Rounding differs from .NET on several engines. #6100 (open, DuckDB: `Math.Round` / `Sql.Round` with a non-constant precision on a decimal fails), #6263 (open, DB2: `Math.Round(double, digits)` to-even differs from .NET at a double tie), #6266 (open, PostgreSQL: `Math.Round` away from zero on a double is wrong near a midpoint and above 2^52), #6273 (open, Firebird: `Math.Round` on a double rounds values just below a midpoint up), #6275 (open, DuckDB: `Math.Round` with a precision on a large decimal overflows or loses digits). The YDB `Math.Floor` / `Ceiling` / `Truncate` case #6041 is in the member theme.
- **Translation output shape: redundant or non-pure SQL nodes** -- #6246 (open: translator factory `Expression` / `NotNullExpression` build non-pure SQL expressions), #5963 (open: a redundant non-mandatory SqlCastExpression built by a provider is not reduced), #5851 (open: a constant `WITHIN GROUP` / `KEEP` sort key in `Sql.Window` still reaches the server verbatim).
- **First/Single and FirstOrDefault through subqueries** -- #6253 (open: an option for LINQ semantics of First()/Single() read through a subquery), #5985 (open: an outer column in a correlated FirstOrDefault calculation under PreferClientCalculation is referenced out of scope).
- **Translation-time cost** -- Query translation cost grows with the shape of the tree. #6279 (open: translation time and memory grow exponentially with a left-deep chain of `+` in a predicate), #5911 (open: query translation runs the whole-tree expression optimizer five times per build).
- **Singleton open items (no recurring cluster)** -- Open EXPR-TRANS-tagged items that match no recurring topic: #6144 (query-filter DefaultIfEmpty promotion in AssociationHelper is always overridden), #6154 (nested FromSql converts its arguments under the outer query mapping schema), #6228 (comparing Sum() of a value-converted column with a parameter does not convert the parameter), #6239 (Delete() over a projected optional association deletes from the root table), #6269 (open decision: whether extension and table-function attribute lookups follow the MappingSchema of a table handle), #5838 (InsertWithOutput/UpdateWithOutput on an inheritance-mapped table read the key as the discriminator), #5303 (6.0.0 regression: different result count when selecting different properties), #5951 (internal analyzer: build steps must use the MappingSchema of the source sequence).

## Resolved themes
- **String method translation consolidation** -- #5613 (string.CompareTo), #5544 (string.IsNullOrWhiteSpace), #5504 (string.Concat across all providers, merged 2026-05-15) -- moved from legacy `Sql.Extension` into the member-translator pipeline with per-provider overrides. #5984 (closed 2026-11-05: SQLite `string.Join` over object items concatenated an arithmetic item without parentheses).
- **Expression optimization post-AST refactor** -- #5570 (collapse nested case-conversion wraps in Guid-to-string translation), #5567 (restore IS NULL pushdown through SqlConcatExpression), #5566 (skip bogus IS NULL guards on non-null Sybase concat operands), #5569 (Sybase concatenation to ANSI ||), #5602 (MA0006/MA0154 fixes for #5570). All post-#5504 string-concat AST refactor.
- **Correlated subquery detection & validation** -- #5574 (reject unsupported correlated subqueries in expression position on ClickHouse/YDB), #5558 (fix InvalidCastException in APPLY-to-JOIN conversion with correlated Contains). #6024 (closed 2026-10-12: the Oracle 11 query validator rejected IS NOT NULL on a column subquery's own table as a parent reference; fixed by PR #6027, merged 2026-10-12). #6210 (closed 2026-11-10: the `Select(Math.Max(...)).Sum()` translation regression in correlated subqueries, fixed).
- **Nullable type handling in subqueries & correlated contexts** -- #5586 (Nullable<T>.HasValue over unbound members, merged 2026-06-19), #5582 (null-safe IN/NOT IN emulation, merged 2026-06-04). #6064 (closed 2026-10-22: an IN list beside a decimal aggregate wrote captured values at the schema default scale). #6120 (closed 2026-11-10 per index: negating a bool built from a nullable comparison dropped rows where the value is NULL).
- **Type translation & casting** -- #5605 (SqlServer decimal overflow fallback via SqlDecimal, merged 2026-07-11), #5466 (DateTimeOffset.DateTime as cast, merged 2026-06-05), #5581 (nullable DateTime subtraction, merged 2026-06-12).
- **TimeSpan & date-difference translation** -- #5750 (TimeSpan members and date differences as elapsed time, merged 2026-08-21), #5739 (native TimeSpan translation, closed), #3994 (original TimeSpan WIP, closed; its binary/unary fixes were carried by #5212).
- **ClickHouse date translation regression** -- PR #5959 (closed: ClickHouse date operands coerced to DateTime64 before the epoch functions, fixing a regression from #5750). #5955 (closed: ClickHouse datetime function regression in 6.5.0). #5960 (closed: `GetDbDataType` discarded a SqlExtendedFunction's declared type for the schema default). #6115 (closed: `.TimeOfDay` on an undeclared DateTime column failed with Code 43, a regression from #5959).
- **Binary/unary operator translation** -- #5212 (merge binary/unary translation fixes from #3994), closed 2026-08-19 without a merge record in the index.
- **Window Functions API** -- #5468 (new Sql.Window fluent API, merged 2026-07-03) replaces the older `Sql.Ext().Over().ToValue()` pattern. #5725 (fold boolean expressions used in window clauses and arguments, merged 2026-09-05).
- **Projection & materialization edge cases** -- #5587 (spurious [item] column on local-collection LEFT JOIN with decimal projection), #5577 (expand member/method mappings during initial expose), #5581 (nullable DateTime subtraction in final projection), #5818 (set-operation projection rejecting an untranslatable concat operand, merged 2026-08-30).
- **Missed LEFT JOIN calculation** -- #5932 and #5923 (both closed 2026-10-21): a non-nullable member of a missed LEFT JOIN row was read as `default(T)` but calculated over NULL in SQL, and `Sql.ToNullable` over a binary expression returned a value instead of NULL under `PreferClientCalculation`. Fixed by #5983 (merged 2026-10-21): projection calculations read such a column as `COALESCE(col, default(T))`.
- **FromSql / Sql.Expr query cache** -- #6000 (closed 2026-10-16: the query cache reused stale SQL when `FromSqlScalar` was nested in an `IN`) and #5857 (closed 2026-10-16: the registered `FormattableString` was compared by reference, so the query was rebuilt on every execution). Fixed by PR #6003 (merged 2026-10-16). PR #6007 (merged 2026-10-13) stops `ConvertToExists` from editing the cached statement, and PR #6008 (merged 2026-10-19) replaces raw SQL arguments the format never references with NULL. #5769 (closed 2026-09-03) is the earlier expression-caching case.
- **Set-operation operand comparison & value converters** -- #5976 (closed 2026-10-09, no merge record: Concat and Union raised "operands for operator NotEqual do not match" with EF Core value converters). #6052 (closed 2026-10-16: Union over columns sharing a value converter class threw "Argument types do not match". The defect was fixed in 6.5.1 by #5978, and PR #6060 (merged 2026-10-16) adds the regression test for that shape).
- **Interface-typed property access** -- #4199 (closed 2026-10-21): "Property X is not defined for interface type Y" after a Select casts to a concrete type. Fixed in 6.0.0-preview.1 by #3401; the test was rewritten to the issue repro by PR #6097 (merged 2026-10-21) and its gate removed.
- **Lifted struct members from an inner projection** -- #6090 (closed: "Property is not defined for type Nullable<T>" when a nullable struct built in an inner projection is read), PR #6091 (closed: `CorrectTrackingPath` builds member access on the constructed type), #6068 (closed: a struct referenced twice failed with "Coalesce used with type that cannot be null"), PR #6069 (closed, fixes #6068), #4773 (closed: casting to an interface plus an association failed during SQL generation).
- **Eager-load nullable association** -- #6208 (closed: eager-loading a nullable QueryExpressionMethod association that contains a join dropped parent rows, because OUTER APPLY became INNER JOIN; regression in 6.x).
- **Expression-tree node coverage** -- #5879 (closed: IndexExpression in a query tree threw NotSupportedException from PathVisitor; the same visitor gap is open in #6142).
- **Math rounding** -- PR #5943 (closed: widened the scaled intermediate in YDB's ROUND emulation).

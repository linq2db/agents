# DATA

## What this area does

`Source/LinqToDB/Data/**` is the **public `LinqToDB.Data` namespace** -- the persistent-connection facade (`DataConnection`), raw-SQL command surface (`CommandInfo` + `DataContextExtensions.Query`/`Execute`/`ExecuteReader` overloads), bulk-copy entry points (`DataContextExtensions.BulkCopy`/`BulkCopyAsync`), tracing primitives (`TraceInfo`, `TraceInfoStep`, `TraceOperation`), the retry-policy framework (`IRetryPolicy`, `RetryPolicyBase`, `RetryingDbConnection/Command`), and the option records that feed `DataOptions` from this layer (`ConnectionOptions`, `BulkCopyOptions`, `QueryTraceOptions`, `RetryPolicyOptions`). Compared to [CORE](../CORE/INDEX.md), DATA is the *ADO.NET execution site*: it owns `DbConnection`/`DbCommand` lifecycle, parameter binding, reader materialization, transactions, and the `IQueryRunner` implementation that hands prepared SQL off to the ADO provider. AST construction, builder dispatch, and SQL emission are out of scope -- see [SQL-AST](../SQL-AST/INDEX.md), [EXPR-TRANS](../EXPR-TRANS/INDEX.md), [SQL-PROVIDER](../SQL-PROVIDER/INDEX.md).

## Inbound dependencies

- [CORE](../CORE/INDEX.md) -- `IDataContext`, `DataContext`, `DataOptions`, `DataExtensions` all depend on `DataConnection` directly.
- [LINQ](../LINQ/INDEX.md) -- `Query`/`Query<T>` materialize results through `IDataContext.GetQueryRunner` which on `DataConnection` returns the nested `QueryRunner`. The eager-loading enumerator reuses `QueryRunner.RunGroups[Async]`, `ExecuteCombined[Async]`, `ExecuteCombinedHarvest[Async]`, `WalkCombinedResultSets[Async]`, `RenderCombinedBatchTemplates` and `DataConnection.IsProcessQueryOverridden` (all `internal`).
- [INTERCEPTORS](../INTERCEPTORS/INDEX.md) -- `DataConnection` implements eight `IInterceptable<...>` slots and invokes them at every command-execute / connection-open / transaction / reader-dispose boundary. A registered `ICommandInterceptor` disables the DbBatch path (`CanRunDbBatch`).

## Recurring patterns

- **Sync/async sibling methods.** Every execution method has a paired sync method in `DataConnection.cs` and async method in `DataConnection.Async.cs`. The async version is hand-written and structurally identical, with `await ... .ConfigureAwait(false)` everywhere and `ActivityService.StartAndConfigureAwait` for activity spans. The source carries explicit `// In case of change the logic of this method, DO NOT FORGET to change the sibling method.` comments at every pair (now also on `ExecuteSingleStepAsync`, `WalkCombinedResultSetsAsync`, `ExecuteCombinedHarvestAsync`, `RunGroupsAsync`, `ExecuteScenarioAsync`).
- **Trace wrapper triplet.** Every traceable op runs `BeforeExecute` -> action -> `AfterExecute`/`Error` via `TraceAction`/`TraceActionAsync` (reader execution: `TraceExecuteReader[Async]`). The wrapper formats a SQL string lazily via `commandText?.Invoke(context)` only when `TraceSwitchConnection.TraceInfo` is set.
- **Interceptor-then-fallback.** Inside command-execute methods the pattern is if `IInterceptable<ICommandInterceptor>`.Interceptor is set, ask it first, return its `Option<T>` if `HasValue`, else fall through to the raw provider call. The DbBatch path has no such step (see Known issues).
- **`CheckAndThrowOnDisposed` discipline.** Every public/internal method that mutates or reads connection-bound state starts with `CheckAndThrowOnDisposed()`.
- **Obsolete-with-`v7`-marker convention** (matches CORE). The 16 ctor overloads at the top of `DataConnection.cs:43--482` are all obsoleted in favor of `DataConnection(DataOptions)`.
- **`record` option types with `ConfigurationID` cache.** Every option type is a sealed `record`, implements `IConfigurationID.ConfigurationID` via a one-shot `IdentifierBuilder` that hashes every parameter, and overrides `Equals`/`GetHashCode` to compare on `ConfigurationID`.
- **`ConfigurationApplier` Apply/Reapply pair.** Same pattern as the CORE `DataContext.ConfigurationApplier`. Lockstep changes to `DataConnection.Configuration.cs` and the option `IReapplicable<DataConnection>`.Apply are required when adding option fields.
- **C# 14 field-backed property setters on `Default`.** `BulkCopyOptions.Default` and `ConnectionOptions.Default` use the C# 14 field-backed property setter syntax. `QueryTraceOptions.Default` and `RetryPolicyOptions.Default` use an explicit backing field (`_default`) instead -- both patterns call `DataConnection.ResetDefaultOptions()` and `ConnectionOptionsByConfigurationString.Clear()` in the setter to invalidate cached configurations.
- **Single parameter-creation seam.** Both DATA parameter-binding sites (`QueryRunner.CreateParameter`, `CommandInfo.SetParameters`) build parameters via `IDataProvider.CreateParameter(dataConnection, command, DataProviderParameterContext)`, with `isDbDataTypeExplicit` distinguishing user-specified `DbDataType` from inferred.
- **Prepare once, render statement-free (sha f90c5bcf).** Cache only the rendered `BakedQuery` (no `SqlStatement` or aliases), keep the parameter-independent structure in a local, and rebuild per run for parameter-dependent or hinted queries.

## Known issues / debt

- **Pinned anchor `BulkCopy.cs` does not exist.** `kb-areas.md` row for DATA lists `BulkCopy.cs` as a Tier-1 anchor. The file is not on disk. The actual bulk-copy public surface is split between `DataContextExtensions.BulkCopy*` overloads (DATA, Tier 2) and the strategy implementations under `Source/LinqToDB/Internal/DataProvider/**` (out of DATA scope).
- **Sixteen obsoleted `DataConnection` ctors slated for v7 removal.** Lines 39--482 of `DataConnection.cs` are almost entirely obsoleted ctor overloads. They forward to `DataConnection(DataOptions)`.
- **Several public properties retain obsoleted setters that are scheduled to become private in v7.** `RetryPolicy`, `OnTraceConnection`, `TraceSwitchConnection`, `WriteTraceLineConnection`, `IsMarsEnabled`, `Connection`, `CreateCommand`, `DisposeCommand`, `DisposeCommandAsync`, `EnsureConnectionAsync`, `ClearObjectReaderCache`, `ThrowOnDisposed`.
- **`LegacyMergeExtensions` is class-level `[Obsolete]`.** The whole 745-line file is deprecated.
- **`CommandInfo.ClearObjectReaderCache` is a globally-shared cache point.** The static `_objectReaders`, `_dataReaderConverter`, `_parameterReaders` `MemoryCache` instances are process-wide and not partitioned by `DataConnection` instance.
- **Single shared `_command` field reused across executions.** After `ExecuteReader`, the command is detached (`_command = null`) and ownership transfers to `DataReaderWrapper`.
- **Former DROP-then-X swallow loop is gone (sha f90c5bcf).** The old rule (intermediate command starting with `DROP` had its exceptions ignored, `-1` returned from the runner's multi-command ExecuteNonQuery) was removed together with the per-index command loop. Multi-step DML now runs through the scenario interpreter, which propagates step exceptions. No in-DATA replacement was found, so any drop-if-exists behavior must now live in the scenario's step gating or provider DDL. Unverified for provider DDL scenarios, confirm before relying on it.
- **`TransientRetryPolicy` is gated behind `ADO_IS_TRANSIENT` (.NET 6+ only).** Means net462/netstandard2.0 callers cannot use the cross-provider transient-retry policy.
- **Obsolete `BulkCopyOptions` copy ctors retained for binary compatibility.** The 20-parameter and (since sha 05150894) 21-parameter overloads are marked `[EditorBrowsable(Never)]` and `[Obsolete(...)]`, forwarding `default` for the trailing `ConflictAction` / `MaxSqlLengthForBatch` parameters to the 22-parameter primary ctor (`Source/LinqToDB/Data/BulkCopyOptions.cs:169--285`). Both will be removed in v7.
- **`CreateObjectReader<T>`'s bespoke non-scalar reflection path is gone (prior delta), superseded entirely by `RecordReaderBuilder`.** No known behavioral regression identified from reading the diff, but the removed path had handled anonymous/no-parameterless-ctor types via a constructor-parameter-name-match heuristic inline. Confirm `RecordReaderBuilder` (LINQ area) covers that heuristic if a future raw-SQL materialization regression surfaces for constructor-bound anonymous-like types.
- **Parameter-dependent queries no longer convert twice (sha f90c5bcf, supersedes the 05150894 note).** They now apply value-dependent refinements (IN-list expansion, null-fold, TAKE/SKIP, InsertOrUpdate SET cast narrowing, ClickHouse `bitAnd`-style conversions) in the single per-run whole-query convert, and the renderer does not re-convert. The source labels this a POC ("decouple builder from optimizer, milestone 1"), so the `singleContext` branch of `GetCommand` is expected to change.
- **DbBatch path bypasses `ICommandInterceptor`.** Interceptors are `DbCommand`-typed, so `CanRunDbBatch` turns batching off whenever one is registered. Tracing and the exception interceptor still apply. A DbBatch-aware interceptor surface is a TODO (#6230).
- **Result-set alignment premise in `WalkCombinedResultSets`.** Group harvesting assumes a pure non-query step yields no result set (SqlClient behavior). A provider that returns one result per statement (Npgsql) would misalign a NonQuery-then-Scalar group and silently return null. Unreachable today (PostgreSQL renders RETURNING, and eager groups are all Reader steps), but a trap for the first such multi-step scenario.
- **DbBatch exception handling asymmetry.** If `ExecuteBatchDataReader[Async]` throws before the reader wrapper takes ownership, `ExecuteCombined[Async]` disposes the batch in a catch. Otherwise the batch lives until `DataReaderWrapper.Dispose` runs, so a leaked wrapper leaks the batch.

# L2DB1003: Declare a server-side-only stub, or implement it

|            |                            |
|------------|----------------------------|
| Category   | LinqToDB                   |
| Severity   | Info (configurable)        |
| Package    | [`linq2db.Analyzers`](https://www.nuget.org/packages/linq2db.Analyzers) — comes in with [`linq2db`](https://www.nuget.org/packages/linq2db), no extra reference needed; reference it directly only to run the rule against an older linq2db |

## Cause

A member's entire body is a single `throw` — a stub — but nothing declares it server-side only.

## Rule description

A member that only makes sense inside a query is declared server-side only, and its body is then a stub that throws if anyone calls it directly. When the declaration is missing, linq2db is free to pick the member for client-side evaluation, and the call fails at run time instead of translating to SQL.

linq2db recognises four ways to declare it, and this rule accepts any of them:

- `[ServerSideOnly]`;
- an `Sql.Expression`-derived attribute whose `ServerSideOnly` is true — note that **every `Sql.Extension` constructor sets it**, so a bare `[Sql.Extension("…")]` already counts with nothing written;
- an `Sql.TableFunction`-derived attribute, such as `[Sql.TableExpression]`;
- `[ExpressionMethod]`, whose member is rewritten to its expression before evaluation.

## When the rule fires

There are two cases, and they differ in how much evidence the rule requires.

**An attribute is present that could carry the marker, but doesn't.** The attribute already declares the member translatable, so *any* throwing body is a contract gap:

```csharp
[Sql.Function("MY_FUNC")]                          // no ServerSideOnly
public static int MyFunc(int x) => throw new NotImplementedException();   // L2DB1003
```

**No such attribute is present.** Then the only evidence of intent is the exception itself, so the rule fires **only** for `ServerSideOnlyException`:

```csharp
// L2DB1003 - throwing ServerSideOnlyException says what this member is
public static int MyFunc(int x) => throw new ServerSideOnlyException(nameof(MyFunc));

// not reported - an ordinary unfinished method, not a server-side-only stub
public static int NotDoneYet(int x) => throw new NotImplementedException();
```

That second rule is deliberate: `throw new NotImplementedException()` is the default IDE stub, and treating it as a declaration of intent would flag every placeholder in your project.

## When the rule does not fire

- A marked member with a **real body** is valid and never reported. Inside a query it emits mapped SQL; outside one the body runs. That is a supported pattern, not a defect.
- Constructors, operators and indexers. A constructor cannot carry `[ServerSideOnly]` at all — the attribute's usage is `AttributeTargets.Property | Method`, which excludes `AttributeTargets.Constructor` — so a fix there could not compile. Operators and indexers *can* carry it (an operator declaration takes method-targeted attributes, and an indexer is a property); they are outside the rule's scope by choice.
- A `set => throw` beside a real getter — the property is not a stub.
- A `throw` that is a `switch` arm, a ternary or a guard clause rather than the whole body.
- Generated code — a `*.generated.cs` file, or any file with an `<auto-generated>` header, including a data model scaffolded by `linq2db.cli`. You maintain those through the tool that emits them, so the rule stays out of the way.

## How to fix

Either declare it, or give it a real implementation. The code fix does the first — adding `[ServerSideOnly]`, or setting `ServerSideOnly = true` on the attribute already there. Implementing the body is not a mechanical rewrite, so it is only named in the message.

```csharp
[Sql.Function("MY_FUNC", ServerSideOnly = true)]
public static int MyFunc(int x) => throw new ServerSideOnlyException(nameof(MyFunc));
```

Note that fixing this rule can surface [L2DB1004](https://github.com/linq2db/linq2db/wiki/L2DB1004): once the member is marked, its stub's exception type comes into scope.

## Options

Widen the set of exception types that mark an **unattributed** stub as server-side only. The list is **additive** to the `ServerSideOnlyException` default and matches type names **exactly**, not by subclass:

```ini
linq2db.L2DB1003.unmarked_stub_exception_types = MyCompany.ServerSideException
```

## How to suppress or change severity

```ini
dotnet_diagnostic.L2DB1003.severity = warning
dotnet_diagnostic.L2DB1003.severity = none
```

Every rule linq2db ships is in the `LinqToDB` analyzer category, so one line covers the whole set:

```ini
dotnet_analyzer_diagnostic.category-LinqToDB.severity = warning
```

To turn the analyzers off entirely for a project — including when they arrive as a dependency of `linq2db` rather than as a direct reference:

```xml
<PropertyGroup>
	<EnableLinqToDBAnalyzers>false</EnableLinqToDBAnalyzers>
</PropertyGroup>
```

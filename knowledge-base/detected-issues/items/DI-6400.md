# DI-6400 — OptimizationContext public type and most public members lack XML docs

**Severity**: low  **Category**: doc-gap  **Status**: open

## Location
- `Source/LinqToDB/Internal/SqlProvider/OptimizationContext.cs:13` — public sealed class without summary
- `Source/LinqToDB/Internal/SqlProvider/OptimizationContext.cs:20` — DataOptions, SqlProviderFlags, MappingSchema, ConvertVisitor, OptimizerVisitor properties undocumented
- `Source/LinqToDB/Internal/SqlProvider/OptimizationContext.cs:31` — public constructor without docs
- `Source/LinqToDB/Internal/SqlProvider/OptimizationContext.cs:53` — EvaluationContext, IsParameterOrderDependent, Factory undocumented
- `Source/LinqToDB/Internal/SqlProvider/OptimizationContext.cs:57` — HasParameters, GetParameters undocumented
- `Source/LinqToDB/Internal/SqlProvider/OptimizationContext.cs:72` — AddParameter (non-trivial dedup and sharing logic) undocumented
- `Source/LinqToDB/Internal/SqlProvider/OptimizationContext.cs:171` — SuggestDynamicParameter, ClearParameters, Optimize undocumented

## Pattern matched
Public API method without summary XML doc. The type is public and is the central render-time context, yet only a few members (ShareParametersByAccessor, PromoteParametersForSharing, NormalizeParameterName, OptimizeAndConvertAll) are documented.

## Why it matters
AddParameter and ClearParameters carry subtle invariants (dedup map reset at group boundary, order-dependent providers bypass the map). A provider author extending the pipeline has no contract text to rely on.

## Suggested fix
Add summaries to the type and public members, at least AddParameter, ClearParameters, SuggestDynamicParameter and the constructor parameters.

# DI-3652 - Empty or no-op catch block

**Severity**: med  **Category**: code-smell  **Status**: open

## Location
- Tests/Linq/Linq/RemoteContextTests.cs:253 - empty catch
- Tests/Linq/Linq/RemoteContextTests.cs:300 - empty catch

## Pattern matched
Catalog row: catch block with empty body or only an ignore comment.

## Why it matters
An empty catch swallows any exception, so a real failure in setup or cleanup is invisible. It can mask provider regressions and leave stale tables behind.

## Suggested fix
Catch only the specific expected exception, or assert/log the failure, and add a comment explaining why ignoring is safe.

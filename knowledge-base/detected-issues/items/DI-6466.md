# DI-6466 — Magic strings and duplicated OUT-parameter scenario in Firebird and Oracle DML services

**Severity**: low  **Category**: code-smell  **Status**: open

## Location
- `Source/LinqToDB/Internal/DataProvider/Firebird/FirebirdDmlService.cs:43` — literal "IDENTITY_PARAMETER", scenario identical to Oracle
- `Source/LinqToDB/Internal/DataProvider/Oracle/OracleDmlService.cs:97` — same literal and scenario
- `Source/LinqToDB/Internal/DataProvider/Firebird/FirebirdDmlService.cs:30` — "GIDENTITY_" + table name, the schema is dropped
- `Source/LinqToDB/Internal/DataProvider/Oracle/OracleDmlService.cs:23` — "SIDENTITY_" and "TIDENTITY_" prefixes mirrored from OracleSqlBuilderBase (per the comment), so two copies must stay in sync

## Pattern matched
Magic string without a shared constant, and duplication between providers (an OutParameter identity scenario next to the base IdentitySelectScenario helper).

## Why it matters
The interpreter that adds the output parameter matches the name literally, and the identity object names must match what the builder uses for CREATE and DROP. A rename in one place silently breaks identity retrieval or drop.

## Suggested fix
Add a shared constant for the parameter name and an OutParameterIdentityScenario helper in DmlServiceBase. Make the builder and the DML service share the name helpers.

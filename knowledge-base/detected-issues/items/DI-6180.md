# DI-6180 — Comment-only catch blocks in test-assembly cleanup

**Severity**: med  **Category**: code-smell  **Status**: open

## Location
- `Tests/Linq/TestsInitialization.cs:494` — `try { File.Delete(work) } catch { /* best effort */ }`
- `Tests/Linq/TestsInitialization.cs:496` — `try { Directory.Delete(dump, true) } catch { /* best effort */ }`

## Pattern matched
Catch block with empty body or only a comment (code-smell, med).

## Why it matters
Cleanup failures in the global test setup are dropped silently, so a leaked temp file or directory leaves no trace in the log and cannot be diagnosed when later runs misbehave.

## Suggested fix
Narrow the catch to IOException and UnauthorizedAccessException, and write the failure to TestContext.Progress as the neighbouring db2 purge block does.

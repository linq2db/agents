# DI-4701 — Firebird char literal does not double a single quote

**Severity**: high  **Category**: code-smell  **Status**: open

## Location
- `Source/LinqToDB/Internal/DataProvider/Firebird/FirebirdMappingSchema.cs:192` — ConvertCharToSql appends the quote char unchanged

## Pattern matched
Localized logic defect (no-op ternary): `value == '\'' ? '\'' : value` returns the same char in both branches, so the escape is never applied.

## Why it matters
For `char` value `'` the literal is emitted as `'''`, which is invalid or unterminated Firebird SQL. The string converter right above doubles quotes correctly, so the char path is inconsistent. Inlined char constants containing a quote produce broken SQL.

## Suggested fix
Emit `''` (two quotes) inside the delimiters when value is a single quote, mirroring ConvertStringToSql. Add a test for an inlined `'` char literal.

# DI-6462 — Only SapHana guards the session-scoped identity SELECT against tables with no identity column

**Severity**: med  **Category**: code-smell  **Status**: open

## Location
- `Source/LinqToDB/Internal/DataProvider/SapHana/SapHanaDmlService.cs:23` — comment claims every sibling provider still has the guard, and the code throws when there is no identity field
- `Source/LinqToDB/Internal/DataProvider/MySql/MySqlDmlService.cs:20` — LAST_INSERT_ID() with no guard
- `Source/LinqToDB/Internal/DataProvider/SQLite/SQLiteDmlService.cs:34` — last_insert_rowid() with no guard
- `Source/LinqToDB/Internal/DataProvider/Access/AccessDmlService.cs:31` — @@IDENTITY with no guard
- `Source/LinqToDB/Internal/DataProvider/SqlCe/SqlCeDmlService.cs:31` — @@IDENTITY with no guard
- `Source/LinqToDB/Internal/DataProvider/Informix/InformixDmlService.cs:33` — DBINFO with no guard

## Pattern matched
Cross-provider inconsistency: one provider has a missing-identity-field check that its siblings lack in these services. The SapHana comment saying siblings still do it is not true here (the check may still live in the builders, not verified).

## Why it matters
For session-scoped identity functions, an insert into a table without an identity column returns a stale value from an earlier insert, silently. Behaviour differs per provider (SapHana throws, the rest do not), and the SapHana comment is misleading.

## Suggested fix
Hoist the guard into IdentitySelectScenario or the base class so every provider gets it, or confirm the builders still enforce it and correct the SapHana comment.

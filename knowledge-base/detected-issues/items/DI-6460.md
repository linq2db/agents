## Pattern matched
Structural duplication (tech-debt / copy-paste between providers). The identical predicate `statement is SqlTruncateTableStatement { ResetIdentity: true } truncate and truncate.Table!.IdentityFields.Count > 0` is repeated in 8 services. Only 4 of them use the base `PerFieldResetScenario` helper, the other 4 rebuild the same "truncate, then raw reset" step list by hand.

## Why it matters
A change to the reset contract (for example the outcome step index, or skipping tables without identity) has to be applied in 8 places. Divergence is already visible: the hand-built variants reset once per table, not per identity field.

## Suggested fix
Move the guard into the base class as a hook (for example a virtual that returns the per-provider reset statement for a field or table) and make the 4 hand-built providers use the shared step shape.

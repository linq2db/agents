# DI-6420 — Mapper exception filter matches provider exception by type-name string

**Severity**: low  **Category**: code-smell  **Status**: open

## Location
- `Source/LinqToDB/Internal/Linq/QueryRunner.cs:99` — Mapper.Map exception filter
- `Source/LinqToDB/Internal/Linq/QueryRunner.cs:535` — BasicResultEnumerable sync loop, same filter
- `Source/LinqToDB/Internal/Linq/QueryRunner.cs:601` — BasicResultEnumerable async loop, same filter

## Pattern matched
Type-name string match (`GetType().Name` compared against a literal). The catalog regex targets `==`, here it is `.Contains("NullValueException", Ordinal)`, so this is a heuristic hit of the same smell. The filter is copy-pasted three times.

## Why it matters
Provider null-value exceptions (SqlNullValueException, OracleNullValueException) are recognised by name because the core library cannot reference those assemblies. A renamed or new provider exception type silently skips the slow-mode remap and surfaces the raw exception.

## Suggested fix
Hoist the predicate into one shared helper (for example a static IsRemappableMappingException method on Mapper) and use it at all three sites. A provider-supplied hook for null-value exception detection would remove the name match entirely.

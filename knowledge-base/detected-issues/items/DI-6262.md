# DI-6262 — build.ps1 carries docfx/analyzer workarounds and a full F# pre-build

**Severity**: low  **Category**: tech-debt  **Status**: open

## Location
- `docs/build.ps1:64-72` — workarounds for dotnet/docfx#8375 and #9775, analyzers and code-style enforcement switched off for the F# pre-build
- `docs/source/docfx.json:101-114` — F# API is read from prebuilt `.build/bin/.../linq2db.FSharp.dll` with hardcoded net462 reference DLLs

## Pattern matched
Build-script debt: workaround comments referencing upstream issues, and a hardcoded build-output layout coupling.

## Why it matters
The F# docs depend on `.build/bin` output paths and TFM folder names. Changing the FSharp project TFMs or output layout silently breaks the F# API pages. The analyzer suppression hides IDE0390/IDE0391 sites that would otherwise fail the Release build.

## Suggested fix
Re-test after the pinned docfx update and drop the workarounds that the upstream issues have since fixed. Resolve the references from the project output (a property-driven path) rather than literal TFM folders.

None open.

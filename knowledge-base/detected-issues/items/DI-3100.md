# DI-3100 - Sync-over-async disposal of owned HubConnection in SignalRDataContext

**Severity**: med  **Category**: perf-smell  **Status**: open

## Location
- `Source/LinqToDB.Remote.SignalR.Client/SignalRDataContext.cs:59` - `Dispose()` blocks on `Task.Run(DisposeOwnedHubConnectionAsync).GetAwaiter().GetResult()`

## Pattern matched
`\.GetAwaiter\(\)\.GetResult\(\)` in non-test code (perf-smell). Mitigated by Task.Run (no sync-context capture) and documented in a comment, hence medium confidence.

## Why it matters
Synchronous Dispose blocks a thread-pool thread for the whole HubConnection shutdown and can stall under thread-pool starvation. HubConnection has no sync disposal, so this is a known trade-off, but it remains a blocking wait on the dispose path.

## Suggested fix
Prefer `DisposeAsync` on the data context where callers allow it, and document sync `Dispose` as best-effort. Possibly dismiss if accepted as intentional.

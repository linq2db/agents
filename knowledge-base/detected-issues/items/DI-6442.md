# DI-6442 — DataConnection.QueryRunner.GetCommand is a ~190-line method with deep nesting and manual lock handling

**Severity**: low  **Category**: code-smell  **Status**: open

## Location
- `Source/LinqToDB/Data/DataConnection.QueryRunner.cs:192` — GetCommand spans lines 192-379

## Pattern matched
Long method (code-smell): one method holds manual Monitor.Enter/Exit with an early release, prepareOnce/continuous/hinted branching, two context builders, rendering, DbBatch template pre-render and caching.

## Why it matters
Lock release is conditional (`continuousRun`) and cached-prepare returns happen inside the try. Every change must reason about the lock state and cache semantics together, which makes edits error-prone.

## Suggested fix
Extract the structure/render-context construction (the two OptimizationContext branches) and the prepared-command assembly into helpers, leaving GetCommand with lock and cache control flow only.

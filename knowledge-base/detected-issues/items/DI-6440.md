# DI-6440 — GetGenericArguments(Type, Type) allocates via Name.Split in a loop and keeps a dead null check

**Severity**: low  **Category**: perf-smell  **Status**: open

## Location
- `Source/LinqToDB/Internal/Extensions/ReflectionExtensions.cs:913` — base-type walk compares `t.Name.Split('`')[0]` per generic base type
- `Source/LinqToDB/Internal/Extensions/ReflectionExtensions.cs:929` — same comparison per generic interface

## Pattern matched
Allocation in a loop (perf-smell): `Name.Split` allocates a string[] and substring per iteration. `baseTypeName == null` is also dead, since `Type.Name` is never null.

## Why it matters
The helper walks the whole base chain and every interface of a type. It allocates on each generic candidate and is not cached. Cost is small per call but it sits in a reflection helper reused by mapping and builders.

## Suggested fix
Compare without allocating (for example `t.Name.AsSpan().StartsWith(baseTypeName)` plus a backtick check, or `IndexOf('`')` and a span compare), and drop the `baseTypeName == null` branch.

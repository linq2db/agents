# DI-6261 — Docs build depends on a personal docfx fork release (single point of failure)

**Severity**: med  **Category**: tech-debt  **Status**: open

## Location
- `docs/docfx-version.json:3` — download URL on `github.com/MaceWindu/docfx/releases`
- `docs/build.ps1:39` — downloads and unzips that artifact on first use
- `docs/source/docfx.json:2` — comment: custom docfx build needed for namespace conflicts (dotnet/docfx#8966)

## Pattern matched
Build-script debt. The site cannot be built with stock docfx. A hash-pinned binary from a personal fork is the only supported toolchain.

## Why it matters
If the release asset is deleted or the fork is abandoned, the docs build and site publishing break. Upgrading docfx means producing a new fork build by hand, and the pin (tag, sha256, sourceCommit) must be refreshed manually.

## Suggested fix
Track upstream fix for dotnet/docfx#8966 and move back to a stock docfx tool, or mirror the artifact under the linq2db organization. Document the refresh procedure next to the pin.

# DI-6463 — IsTableNotFoundExceptionCore is a stub returning false in 8 of 10 providers

**Severity**: med  **Category**: tech-debt  **Status**: dismissed

> **Dismissed 2026-11-11:** this is a false positive. `IsTableNotFoundException` has one caller, `QueryRunner.DropTable.IsTableNotFound`, which suppresses the error only for `DropTable(ifExists)`. Every provider with the stub handles "if exists" in the SQL it emits: native `IF EXISTS` for base, MySQL, DuckDB, Informix and SQLite, or a guarded block for Oracle (`SQLCODE != -942`), SapHana, Firebird, DB2, SqlServer and Sybase. Only Access and SqlCe cannot do it in SQL, and both implement detection.

## Pattern matched
Cross-provider inconsistency: only Access (AccessDmlService.cs:44) and SqlCe (SqlCeDmlService.cs:45) implement detection. The abstract hook was added to the base and the rest satisfy it with a no-op.

## Why it matters
IsTableNotFoundException is used to tolerate a missing table. Providers with a stub always report false, so for example a missing-table error on Oracle (ORA-00942) or MySQL (1051/1146) propagates where Access and SqlCe tolerate it.

## Suggested fix
Implement per-provider detection with the existing TypeOrMessageContains / SQLSTATE helpers, or make the base method virtual returning false so remaining gaps are explicit.

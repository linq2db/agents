### Full release notes (wiki)
<!-- rn:full:start -->
**LinqToDB — Fixed**
- A subquery or association that contains a join, read through `OUTER APPLY` / `CROSS APPLY` (or `LATERAL`), now keeps the join inside it. The join was moved out: on SQL Server, SQL CE and Oracle 12+ an inner join then silently dropped outer rows, and a left join keyed on the outer row returned values for rows that had no match; on MySQL 8 and SAP HANA the generated SQL was invalid:

  ```csharp
  from c in db.Child
  from p in (
      from g in db.GrandChild.Where(g => g.ChildID == c.ChildID).OrderBy(g => g.GrandChildID).Take(1)
      join p in db.Parent on g.ParentID equals p.ParentID
      select p).DefaultIfEmpty()
  select new { c.ChildID, ParentID = p == null ? (int?)null : p.ParentID }
  // SQL Server: children whose GrandChild had no matching Parent were dropped
  ```

  This also affected eager loading of a nullable `[ExpressionMethod]` association that contains a join, and on Oracle 12+ an `UPDATE` from such a subquery wrote `NULL` to rows without a match. Versions up to 5.4.1.9 were not affected.

### Full release notes (wiki)
<!-- rn:full:start -->
**LinqToDB Remote Context — ⚠ Breaking changes**
- gRPC calls cancelled through the caller's `CancellationToken` now throw `OperationCanceledException` (with the original `RpcException` as its inner exception) instead of an `RpcException` with `StatusCode.Cancelled`.

**LinqToDB Remote Context — Added**
- New `GrpcDataContext(GrpcChannel channel, Func<DataOptions, DataOptions>? optionBuilder = null)` constructor: the context sends every call over a caller-owned channel and never disposes it.

**LinqToDB Remote Context — Improved**
- A `GrpcDataContext` created from an address opens one gRPC channel on first use, reuses it for all its calls and disposes it with the context. Previously every call opened a new connection.

**LinqToDB Remote Context — Fixed**
- A cancelled `CommitBatchAsync` over gRPC kept running on the server and committed the batch; the cancellation now reaches the server and the batch is rolled back.
- With `GrpcChannelOptions.DisposeHttpClient = true`, the second query on a context failed because the `HttpClient` had been disposed after the first; it is now disposed with the context.
<!-- rn:full:end -->

### GitHub release highlight (brief)
<!-- rn:brief:start -->
gRPC remote context reuses one channel per context instead of a connection per query, and can run over a caller-owned `GrpcChannel`.

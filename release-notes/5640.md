### Full release notes (wiki)
<!-- rn:full:start -->
**LinqToDB Identity — ⚠ Breaking changes**
- `linq2db.Identity` now ships with LinqToDB and follows its version line, so 6.6.0 directly follows the standalone 6.0.0. Its API is breaking:
  - The stores use the standard ASP.NET Core Identity types (`IdentityUser<TKey>`, `IdentityRole<TKey>`, …) instead of the `IIdentityUser` / `IIdentityRole` interface family.
  - A LinqToDB context registered with `AddLinqToDBStores<TContext>()` replaces `IConnectionFactory`.
  - The default mapping is EF Core's `AspNet*` schema.
  - `Stores.ProtectPersonalData` is not supported.

  Tables that the standalone package's `CreateTable` created are named after the CLR types; rename them, or map the old names in a `ConfigureMappings` override. Don't let a `6.*` version range pick this package up unreviewed.

**LinqToDB Identity — Added**
- Targets net462, netstandard2.0, net8.0, net9.0 and net10.0; the standalone package targeted netstandard2.0 only.
- Passkey storage (`IUserPasskeyStore`) on .NET 10, with `IdentitySchemaVersions.Version3`.
- `UseIdentityDatabaseCascadeDelete()` for databases that cascade deletes themselves. Without it, `DeleteAsync` removes a user's or role's dependent rows itself, since LinqToDB DDL creates no foreign keys.

**LinqToDB Identity — Fixed**
- Fluent table-name mappings were ignored.
- `BulkCopyAsync` recursed into itself until the stack overflowed.
- The claim `Id` was not an identity column.
- `SetTokenAsync` did not update an existing token.
- `UserManager` role operations threw `NotSupportedException`.
- Re-adding a user to a role failed with a primary-key violation.
- `ConcurrencyStamp` was not refreshed after `UpdateAsync`.

**Access — Fixed**
- Over ODBC, a string parameter mapped as `DataType.Text` / `DataType.NText` (a Long Text column) longer than 255 characters no longer fails with `HY104: Invalid precision value`.

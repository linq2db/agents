### Full release notes (wiki)
<!-- rn:full:start -->
**Provider bullets**
- **SQL Server** — a Unicode argument of a string function applied to a `VarChar` column no longer loses its non-ASCII characters:

  ```csharp
  var suffix = "Жук";
  db.GetTable<T>().Select(t => Sql.AsSql(t.Code.Replace("A", suffix)))   // Code is VarChar(50)
  // returned "???-100"
  ```

  The same applied to `Sql.Replace`, `Replace(char, char)`, the padding character of `PadLeft`, and `CompareTo`, `TrimEnd` and `Sql.Like` over such a concatenation; a non-Latin search value could also match a real `?` in the column. Such an argument is now sent with the default string type, and a non-ASCII literal as `N'…'`.
- **SQL Server** — known limitation: a `Replace` or `PadLeft` result beside a `VarChar(n)` column with `n ≤ 4000` is now cut at 4000 characters when it grows longer and a Unicode argument is involved ([#6236](https://github.com/linq2db/linq2db/issues/6236), [#6238](https://github.com/linq2db/linq2db/issues/6238)).

### Full release notes (wiki)
<!-- rn:full:start -->
**LinqToDB Packages — ⚠ Breaking changes**
- `linq2db.SapHana` and `linq2db.t4models` no longer ship `Sap.Data.Hana.v4.5.dll`, for which no redistribution terms are on record ([#5862](https://github.com/linq2db/linq2db/issues/5862)). Scaffolding a SAP HANA database from the T4 templates with the native provider now needs a SAP HANA client installed, which registers `Sap.Data.Hana` in `machine.config` and puts `Sap.Data.Hana.v4.5` in the GAC. ODBC scaffolding is unaffected.

**SAP HANA — Added**
- On .NET 10 the native provider `Sap.Data.Hana.Net.v10.0` is now detected and preferred, ahead of the v8.0 and v6.0 clients.

**LinqToDB CLI — Added**
- On .NET 10, scaffolding SAP HANA with the native provider now looks for `Sap.Data.Hana.Net.v10.0.dll`.

**LinqToDB LINQPad Driver — Improved**
- On LINQPad 8 and later, the native SAP HANA provider is now provisioned from SAP's `Sap.Data.Hana.Net.v8.0` NuGet package, so you no longer have to point the driver at a SAP HANA client installation. SAP HANA is not offered in a Windows ARM64 LINQPad process.

### Full release notes (wiki)
<!-- rn:full:start -->
**Provider bullets**
- **SQL Server** — a Unicode value concatenated with a `VarChar` column no longer loses its non-ASCII characters; the value was sent as a `VarChar` parameter typed after the column:

  ```csharp
  var suffix = "Жук";
  db.GetTable<Product>().Select(p => Sql.AsSql(p.Sku + suffix))   // Sku is VarChar(20)
  // returned "A-100???"
  ```

  Comparisons such as `p.Title == p.Sku + suffix` and `titles.Contains(p.Sku + suffix)` matched no rows for the same reason. The value is now sent with the default string type (`NVarChar(4000)`); comparing or updating a `VarChar` column with a plain value still sends a `VarChar` parameter.
- **SQL Server** — known limitation: such a concatenation beside a `VarChar(n)` column with `n ≤ 4000` is now cut at 4000 characters when its result is longer ([#6212](https://github.com/linq2db/linq2db/issues/6212)).

**LinqToDB — Fixed**
- A value combined with a value-converted column or its `SUM` now goes through the column's converter only where it is in the column's stored unit. With a ×100 converter, `g.Sum(x => x.Cents) == 7` found no group, `x.Cents * 2` returned `600` instead of `6`, and `g.Sum(x => x.Cents) % 2` returned `0` instead of `1`. Added, subtracted, compared and modulus values are converted; factors and divisors are not.

### Full release notes (wiki)
<!-- rn:full:start -->
**LinqToDB — Fixed**
- Since 6.5.1, an operator between columns whose value converters differ is refused ([#5902](https://github.com/linq2db/linq2db/pull/5902)). A `DateTime` and a `DateTime?` member that use the same conversion were refused too — e.g. the nullable one spelled `v => v != null ? F(v.Value) : null`, or an EF Core nullable converter delegating to the plain one — failing with "could not be converted to SQL". Such a pair is now recognised as stored the same way; pairs that cannot be shown to convert the same way are still refused.
- Two fluent mapping schemas that convert the same member with different converters no longer share one of them; the first schema's converter was silently used for both.

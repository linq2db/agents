#### Combined commands

With `UseCombinedCommands` on, LinqToDB sends work that used to take several round trips as one command on SQLite, SQL Server, MySQL and PostgreSQL:

```csharp
var options = new DataOptions()
    .UseSqlServer(connectionString)
    .UseCombinedCommands(true);

using var db = new DataConnection(options);

var parents = db.Parent
    .LoadWith(p => p.Children)
    .ToList();   // the parent query and the child query travel together
```

- **Eager loading:** the main query and every child query that can be combined are sent together and their result sets read in turn, instead of one round trip per level. `First` / `Single` queries with `LoadWith` combine too.
- **Inserts that return the identity** run as one command.
- **Transport:** an ADO.NET `DbBatch` where the provider supports one (`UseDbBatch`, on by default). Otherwise, or when a command interceptor is registered, the statements are joined with `;` into one command; `UseDbBatch(false)` always uses that joined form.
- **What changes:** the statements share one parameter scope, so the SQL and the trace output look different. SQL Server keeps a combined command under its 2100-parameter limit by splitting it.

The option is off by default in 6.x.

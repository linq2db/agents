### Full release notes (wiki)
<!-- rn:full:start -->
**LinqToDB — Added**
- Opt-in combined commands: `DataOptions.UseCombinedCommands(true)` (also `LinqOptions.UseCombinedCommands` and `Configuration.Linq.UseCombinedCommands`). On SQLite, SQL Server, MySQL and PostgreSQL, an eager load (`LoadWith` / `ThenLoad` with collection children) then sends the main query and its child queries in one round trip, and an insert that returns the identity becomes a single command. Other databases keep running the queries one by one. Off by default.

**LinqToDB — ⚠ Breaking changes**
- An eager load outside a transaction now reads all its main rows and commits its consistency transaction before returning the first row. Code in the loop body, such as writes in an `await foreach` / `ForEachAsync` body, no longer runs inside a transaction it did not open, so those writes are no longer rolled back with it. A loop that stops early still reads every main row, and an exception from the projection of any row now fails the query before the first row is returned.
- On databases with a boolean type, a C# comparison of nullable operands used as a value — a conditional branch, an `UPDATE` set value, an `ORDER BY` key, a set-operation column — now reads `false` when an operand is `NULL`, as in C#; it read `NULL` before.
- A negated comparison with a `NULL` parameter, `!(x.Value <= p)` with `p == null`, now matches every row, as in C#.

**LinqToDB — Improved**
- Generating SQL for a query is faster and allocates less, most noticeably for compiled inserts and updates and for queries whose SQL depends on parameter values.

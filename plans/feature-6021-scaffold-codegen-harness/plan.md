# Work plan: feature-6021-scaffold-codegen-harness — Scaffold code-generation test harness (schema → generate → compile → execute), C# + F#

**Tier:** L  ·  **Status:** approved  ·  **Approved-at:** 2026-10-12 (user, after critic round 1 `weak` folded in) ·  **Branch:** feature/6021-scaffold-codegen-harness (stacked on `feature/1553-fsharp-codegen`, PR #5707)
**Schema:** `.claude/docs/work-plan.md`  ·  **Gates:** `.claude/docs/definition-of-done.md`

## P1 Problem

[#6021](https://github.com/linq2db/linq2db/issues/6021). Scaffolder output is verified only by compiling committed goldens that CI never regenerates. Those goldens are `Tests/Tests.T4/Cli/**` (regenerated by hand via T4 `RunCliTool()`) and `Tests/FSharp.Scaffold/**` (regenerated by hand via `generate.ps1`). Two consequences:

- **(a)** A generator change made without regenerating passes CI.
  - Falsifiable: break keyword escaping at `FSharpCodeGenerator.cs:1515` or `CSharpCodeGenerator.cs:1054` today. Every per-PR job stays green, because `build.yml` compiles only the stale goldens and `Tests/Linq` is `/azp`-dispatched.
- **(b)** A generator feature is covered only when some test database happens to contain a matching object. Uncovered today:
  - keywords as names;
  - schema-qualified objects;
  - option combinations that no golden set uses;
  - all 15 `ScaffoldInterceptors` hooks — no test constructs a subclass (searched `ScaffoldInterceptors|LinqToDBHost` over `Tests/`; only `Tests/Tests.T4/Cli/scaffold.tt` matches);
  - the CLI `--customize` path — no test.
- **Existing precedent:** `Tests/Linq/Scaffold/FSharpCodeGenerationTests.cs` (in-test `ISchemaProvider` at `:496`) and `SqlServerDecimalOverflowProtectionTests.cs` assert on generated text only. Nothing compiles or executes freshly generated code in CI.

## P2 Success criteria

- SC-1 The harness turns an in-test schema plus options into C# and F# source with the current generator, compiles it in-process, and loads it. A compile error or an unallowlisted warning fails the test with diagnostics plus the line-numbered source. → TO-1a TO-1b TO-1c TO-1d
- SC-2 A generator regression that breaks compilation (keyword escaping) turns a per-PR test red without any golden being regenerated. → TO-2a TO-2b
- SC-3 A generator regression that compiles but misbehaves at runtime (lost fluent mapping, wrong column name mapping) turns a per-PR test red through execution on in-memory SQLite. → TO-3a TO-3b
- SC-4 Per-feature coverage, for both languages, of each element enumerated in TO-4…TO-9: option matrix, identifiers, nullability, metadata, associations, find methods, multi-schema. → TO-4a…TO-9e
- SC-5 Features SQLite cannot execute get per-PR coverage through SqlServer/PostgreSQL provider profiles: compile with provider-specific types, plus SQL text from `ToSqlQuery()` for table/scalar/aggregate functions. → TO-10a…TO-11b
- SC-6 Generated procedures and functions execute on real SqlServer and PostgreSQL in the provider legs, against objects that already exist in the init scripts. → TO-13a…TO-13h
- SC-7 Each of the 15 `ScaffoldInterceptors` hooks has an observable effect on the compiled/executed output, in both languages, or a stated reason why it cannot be observed. → TO-12a…TO-12o
- SC-8 CLI `scaffold --customize` with a `.tt` template and with a `.dll` produces customized output that compiles; the CLI's error exits are pinned. → TO-14a…TO-14e
- SC-9 The three moved DB-free fixtures run in the new project with the same test count, and they run per PR. → TO-15
- SC-10 The new `scaffold-tests` job runs on every PR on ubuntu-24.04 and windows-2025 and is green. → TO-16
- SC-11 #4831 (a view named `Table`) is pinned by a test: green if it already compiles, otherwise `[ActiveIssue(4831)]`. → TO-17
- SC-12 `Tests/Linq` still builds on net462 (harness excluded) and on net8+, and its existing tests are unaffected. → TO-18

## P3 Constraints & anti-goals

- **No product-code change.** Nothing under `Source/` is edited. A generator or CLI defect a new test surfaces is handled per D-10, not fixed on this branch.
- **No public API, no `PublicAPI.*.txt`, no `CompatibilitySuppressions.xml`.** All new code lives in test projects.
- **#5707's temporary measures stay untouched:** the goldens linked into `Tests/FSharp`, `GeneratedCode.fs`, and `Tests/FSharp.Scaffold/*.fsproj` (user decision).
- **`Tests/Linq/Scaffold/FSharpCodeGenerationTests.cs` is not moved** until #5707 merges (user decision, to avoid merge churn). `SchemaProviderTests.cs` stays because it needs real PostgreSQL/SqlServer.
- **No runtime DDL in the provider legs.** Several SqlServer contexts share one physical DB (`DataProviders.json:143-144`, `:159-162`).

## P5 Decisions

### D-1 — Host: standalone per-PR exe `Tests/Tests.Scaffold`
- **chosen:** a new NUnit MTP exe (net10.0) modelled on `Tests/LinqToDB.CLI/Tests.LinqToDB.CLI.csproj`, run by a new `build.yml` job on every PR.
- **rejected:** fixtures inside `Tests/Linq` gated to `SQLite.MS` — these run only on the `/azp`-dispatched `s_SQLite` leg, so (a) in P1 stays true.
- **why this:** user decision. It is the only option that puts generator regressions in front of every PR.
- **failure mode of the choice:** a third copy of the bare-NUnit `--test-progress` trap (U-12), and a new job's runtime added to every PR.

### D-2 — F# compiler: FCS in-process
- **chosen:** `FSharp.Compiler.Service` 43.12.401 (test-only `PackageVersion`), one shared `FSharpChecker` per process.
- **rejected:** out-of-process `dotnet build` of a temporary `.fsproj` — it needs a restore per case and is ~10–30 s per case.
- **why this:** user decision; U-2 measured that it works.
- **failure mode of the choice:** FCS exact-pins `FSharp.Core [10.1.401]`, so a future FSharp.Core bump without an FCS bump fails restore with NU1608 (an error under TreatWarningsAsErrors). This is recorded for the corpus `nuget-package-notes.md` (deferred, P10).

### D-3 — Compile references = host `TRUSTED_PLATFORM_ASSEMBLIES`
- **chosen:** reference every managed `.dll` in the host's TPA (de-duplicated, native images excluded) for both compilers.
- **rejected:**
  - `Basic.Reference.Assemblies` — new package, and it lacks linq2db, provider and FSharp.Core assemblies, which would then need a second list anyway;
  - the CLI's `typeof(X).Assembly.Location` + runtime-folder `System*.dll` list (`ScaffoldCommand.Interceptors.cs:394-413`) — it misses provider assemblies, which the provider profiles need.
- **why this:** each host (Tests.Scaffold, Tests/Linq, CLI tests) already resolves its own provider assemblies, which sidesteps U-6.
- **failure mode of the choice:** compiling against implementation assemblies rather than reference assemblies; 179 references slow the compile (U-5). A host lacking an assembly the generated code needs fails with CS0246, which is loud and points at the host's references.

### D-4 — The harness is a separate class library, with no provider package references
- **chosen:** `Tests/Tests.Scaffold.Harness` (net8.0;net9.0;net10.0), referenced by Tests.Scaffold, by `Tests/Linq/Tests.csproj` for non-net462 TFMs only, and by Tests.LinqToDB.CLI.
- **rejected:**
  - linking the sources into each host — three compiles of the same code and three places to drift;
  - putting the harness in `Tests.Base` — it is net462 and imported everywhere.
- **why this:** one implementation; each host supplies the provider assemblies.
- **failure mode of the choice:** every published `Tests/Linq` net8+ artifact grows by FCS + Roslyn. Leg disk is already tight (`tests.yml:519-521`); sized at G-11.

### D-5 — Provider legs execute only objects that already exist in the init scripts
- **chosen:** the in-test `TestSchema` mirrors the signatures of the U-10 objects; the generated code calls them read-only.
- **rejected:** runtime `CREATE OR ALTER` with case-unique names — SqlServer contexts share databases, and existing tests use fixed names with drop/create (scout §1), so a race is plausible.
- **why this:** zero shared-state risk, and these objects already back `SqlServerTests` / `ProcedureTests` / `PostgreSQLTests` assertions.
- **failure mode of the choice:** the mirrored signatures are hand-written, so init-script drift breaks the test. That failure is loud (wrong parameter count / type at execution), not silent.

### D-6 — Execution is a generic reflection smoke plus targeted reflection asserts
- **chosen:** `ModelSmoke`:
  - for each entity: `CreateTable<T>`, insert sample rows, read them back and compare;
  - call each generated `Find*` method;
  - `LoadWith` each association.
  Feature tests add targeted reflection asserts on top. F#: `DataOptions.UseFSharp()`, records built via their primary constructor, `option` values via `FSharpOption`.
- **rejected:** per-case driver snippets in C# and F# compiled with the generated code — double authoring, and a snippet compile error would be indistinguishable from a generator error.
- **why this:** one execution path for both languages, so a difference between them is a generator difference.
- **failure mode of the choice:** source-level usage idioms, such as extension-method syntax at a call site, are not exercised. A generated `Find` extension is a static method and is invoked as one.

### D-7 — Warnings fail the compile unless allowlisted per call
- **chosen:** C# warnings are treated as errors and F# compiles with `--warnaserror+`. Each test may pass an allowlist of ids with a reason.
- **rejected:** errors-only — that would miss NRT/nullness regressions (CS86xx, FS3261), which consumers building with warnings-as-errors hit first.
- **failure mode of the choice:** a warning on a legitimate shape becomes noise. The allowlist entry has to name the reason, and it is visible in review. The harness suppresses nothing by default, including FS3370 (U-2). If generated code trips a warning, that is either a generator finding (D-10) or an allowlist entry with its reason.

### D-8 — The SQL-text layer asserts structural tokens, not whole strings
- **chosen:** `SqlShape` asserts the presence of the schema-qualified function name, the parameter count, and `GROUP BY` / `FROM <fn>(` placement.
- **rejected:** full-string baselines — brittle to formatter churn (`testing.md:530`).
- **why this:** this is the generation-only exception the user accepted (U-14), and SQL execution happens in the provider legs (SC-6).
- **failure mode of the choice:** a vacuous substring check. Each TO-10/TO-11 row names the mutation that must redden it.

### D-9 — CLI customize tests run out of process, through both `.tt` and `.dll`
- **chosen:** `RunCliProcess`, plus a new overload `RunCliProcess(TimeSpan timeout, params string[] arguments)`; `params` must stay last. The existing signature keeps its 20 s default; the customize tests use 120 s. The `.tt` case reuses `Tests/Tests.T4/Cli/scaffold.tt`'s header contract. The `.dll` case is built by the harness's `CSharpCompiler` to a file. A temporary SQLite file DB comes from `CreateCliSqliteDatabase`.
- **rejected:** in-process `LinqToDBCliController` — the fixed assembly names break a second load in the same host (U-8), and errors go to `Console`.
- **failure mode of the choice:** process tests are load-sensitive (`testing.md:175`). The longer timeout is the mitigation.

### D-10 — Defects the new tests surface are pinned, not fixed here
- **chosen:**
  - An F#-generator defect is fixed on the parent `feature/1553-fsharp-codegen` (#5707, unmerged, same owner), and this branch is then merged forward.
  - Any other generator or CLI defect (incl. U-9) gets an `[ActiveIssue(<n>)]` test here, with `<n>` = an issue filed with user approval or the fix-PR number, and a fix on its own branch.
- **rejected:** fixing in this PR — that bundles separable product fixes into a test-infrastructure PR (`AGENTS.md` → *Creating a new branch*).
- **failure mode of the choice:** a gated test guards nothing until it is un-gated, so the gate cites a tracked number and `/enable-disabled-test` picks it up.

### D-11 — Compile-cost mitigations
- **chosen:** one process-wide `FSharpChecker`; option-matrix coverage via the six explicit combinations in D-12 rather than a full product; fixtures non-parallel (NUnit default) until G-10 measures CI time.
- **rejected:** batching several cases into one compilation — one broken case would fail its neighbours, which destroys per-feature attribution.
- **failure mode of the choice:** the CI job may be slow. G-10 records the measured job time; above 20 min → P11 (reference trimming or parallel fixtures).

### D-12 — Option-matrix combinations (each run for C# and F#)
- C1: NRT on, Attributes, find default, IEquatable off, schema-as-type on
- C2: NRT off, Attributes, find all, IEquatable on, schema-as-type off
- C3: NRT on, Fluent, find all, IEquatable off, schema-as-type off
- C4: NRT off, Fluent, find default, IEquatable on, schema-as-type on
- C5: NRT on, None, find default, IEquatable on, schema-as-type off
- C6: NRT off, None, find all, IEquatable off, schema-as-type on
- These cover every axis value and every metadata × NRT pair. The schema includes an identity column and a two-schema layout, so schema-as-type is actually exercised. ModelSmoke runs for C1–C4; C5/C6 (metadata None) are compile-only, because there is no mapping to execute against.

### D-13 — Names
- **chosen:** assemblies `linq2db.Tests.Scaffold` (exe) and `linq2db.Tests.Scaffold.Harness`, namespace `Tests.Scaffold` (moved fixtures keep theirs) and `Tests.Scaffold.Harness`.
- **rejected:** `linq2db.Scaffold.Tests` — inconsistent with `linq2db.Tests.Analyzers`.
- **failure mode of the choice:** `Tests/Linq` also uses namespace `Tests.Scaffold` (SchemaProviderTests, FSharpCodeGenerationTests). It references only the harness, whose types live under `Tests.Scaffold.Harness`, so there is no type clash (scout §6).

### D-14 — SQLite multi-schema cells map schemas to attached databases
- **chosen:** for SQLite-executed multi-schema cells, `TestSchema` sets each non-default object's `SqlObjectName` to `Schema = <alias>, Database = <alias>`, with `IncludeDatabaseName = true`. `SqliteTestDb.Attach(<alias>)` runs `ATTACH DATABASE ':memory:' AS <alias>`. Schema-as-type still groups on `Schema`, and SQLite renders `Database` (U-17).
- **rejected:**
  - `Schema` only — SQLite drops it, so both same-named entities hit `main` and `CreateTable` fails with "already exists";
  - compile-only multi-schema cells — that would leave schema-as-type output with no SQLite execution at all, while the mapping exists.
- **why this:** it mirrors what the repo's own SQLite schema reader reports (attached aliases as `SchemaName`, `SQLiteSchemaProvider.cs:104,183,198`), so the cells exercise a shape real SQLite scaffolds produce.
- **failure mode of the choice:** the SQLite cells do not exercise the schema-qualified *rendering*, because SQLite has none. Schema rendering is covered by `SqlShape` on the SqlServer/PostgreSQL profiles (TO-9e) and by TO-13e/13f (`TestSchema.SchemaTableFunction`, `"SchemaName"."fnTest"`).

### D-15 — Compiled models are cached per (profile, language, schema-case), and FCS calls are serialized
- **chosen:**
  - `Generator` + compiler results are memoized in a process-wide `ConcurrentDictionary<key, Lazy<CompiledModel>>`, so parallel lanes in `linq2db.Tests` compile each model once per process.
  - `FSharpCompiler` takes a process-wide lock around `Compile`.
  - Every emitted assembly gets a unique simple name (`Gen_<case>_<guid>`), because the default ALC rejects a second assembly with the same simple name.
- **rejected:**
  - `[NonParallelizable]` on E-10 — it takes the write lock (`ResourceLaneDispatcher.cs:30-33`) and stalls every other lane while compiling;
  - unsynchronized FCS calls — concurrency safety is undocumented (U-16).
- **failure mode of the choice:** F# compiles serialize across lanes. Cost: one compile per model per process, which G-10 sizes.

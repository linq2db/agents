## P1 Problem

[linq2db/docs#59](https://github.com/linq2db/docs/pull/59) (sdanyliv, 8 commits, head `refactor/site-reorganization` @ `dfabbec7c`) reorganizes the documentation site into Documentation / Articles / API sections and replaces the landing page (today `docs/source/index.md` = `[!include[intro](../../README.md)]`) with a hero + 7-tab C#/SQL demo. linq2db/docs is being archived (docs live in `docs/` since #6265), so the PR cannot merge where it is, and its commits do not apply to the new layout: #6265 moved `source/` → `docs/source/` and lowercased 15 article paths, so the PR's `source/{articles => documentation}/CLI.md`-style renames name files that no longer exist. Two reviews stand against it — MaceWindu 2026-06-20 (COMMENTED: 2 blocking, 4 minor, 2 nits) and igor-tkachev 2026-07-12 (CHANGES_REQUESTED: 3 blocking, 5 other). Measured defects in the PR as written:
- `index.md` hero claims ".NET Foundation Member" — linq2db has left the .NET Foundation (both reviews, blocking).
- `tools/sql-demo/SqlDemoGenerator.cs:TempTableDemo` is a GROUP BY query with no temp table, while the tab shows `CreateTempTable` + BulkCopy + join (both reviews).
- `SqlDemoGenerator.WindowFunctions` projects `RowNum`, `Rank`, `Total`; the tab shows `RowNum`, `Total` (both reviews).
- `MergeDemo` calls `ToSqlQuery` on the `IMergeable` builder while the tab ends in `.Merge()` (both reviews ask to confirm the output matches).
- `tools/sql-demo/README.md:3` and `:9` call the displayed SQL "the real SQL generated by linq2db" though it is hand-re-indented HTML with no sync check (both reviews).
- `docfx.json` `fileMetadata._disableContribution` covers `api/**/**.yml` only (both reviews ask to cover all generated API output).
- `main.css` `.demo-radio { display: none; }` removes the 7 radios from the tab order, so the demo cannot be operated by keyboard at all, and screen readers get no group semantics (igor #8 raised semantics; the keyboard defect is measured from the CSS, neither review named it).
- `_gitContribute.repo` = `https://github.com/linq2db/docs` — edit links would point at the archived repo.
- Measured on current master (P4 U-3/U-4): the ExpressionMethod, CTE and Merge SQL panes no longer match what linq2db generates (`Coalesce`, aliases, `SET IDENTITY_INSERT`).

## P5 Decisions (M/L; rejected alternatives mandatory at L)

### D-1 — Port by re-applying, not cherry-picking

- **chosen:** one commit authored by sdanyliv (`--author="Svyatoslav Danyliv <sdanyliv@gmail.com>"`, message citing linq2db/docs#59 and its 8 commits) that applies the PR's net content onto the new layout — `git mv docs/source/articles/* docs/source/documentation/` with the lowercased names, his new files (`articles/index.md`, `documentation/index.md`, `documentation/toc.yml`, `index.md`, `main.css`, `toc.yml` hunk, `docfx.json` hunks, `tools/sql-demo/{README.md,SqlDemoGenerator.cs}` → `docs/tools/sql-demo/`) — then our fix-ups as separate commits (E-6…E-12).
- **rejected:** `git am --directory=docs` of the 8 commits — the renames target the pre-#6265 mixed-case paths and fail; resolving them commit by commit reproduces the same net tree with eight conflict resolutions. Squashing everything under our authorship loses attribution (user chose authorship kept).
- **why this:** the net diff is what reviewers already reviewed; the fix-ups map 1:1 to review points.
- **failure mode of the choice:** the authored commit contains our path translation — a reviewer can't tell his bytes from ours. Mitigated: the commit body states the only translations (paths lowercased, `source/` → `docs/source/`, `tools/` → `docs/tools/`, `CLAUDE.md` and screenshots dropped, `toc.yml` keeps master's Compat entry where the PR deleted a commented-out one).

### D-2 — Physical move `articles/` → `documentation/`, update in-repo URLs, no redirects

- **chosen:** move as the PR does; rewrite the 40 in-repo `linq2db.github.io/articles/` URLs (13 files) to `/documentation/` with one scripted replace; no redirects. State the decision as open in the PR body and a PR comment (user: "for now b with pr comment to decide later").
- **rejected:** keep `articles/` and change navigation only (recommended to the user; deferred by them to review). docfx `redirections.yml` — #6265 set the no-redirect policy.
- **why this:** user decision.
- **failure mode of the choice:** URLs printed in shipped artifacts — `[Obsolete]` on `LegacyMergeExtensions` (`Source/LinqToDB/Data/LegacyMergeExtensions.cs:16`), XML docs in `SqlServerTools.cs:56,66`, `SqlServerProviderDetector.cs:48,64`, `SystemDataSqlServerAttributeReader.cs:23`, every published package readme — go 404 for every released version. Recorded in P10; the PR comment names exactly this.

### D-3 — Demo generator: SQLite in-memory for five tabs and Temp Table, offline SQL Server for Merge

- **chosen:** `docs/tools/sql-demo/SqlDemoGenerator.cs` keeps one `[Test]` per tab with the tab's exact C#. Query, Associations, ExpressionMethod, CTE, Window Functions use `UseSQLite` + `ToSqlQuery(InlineParameters = true)` (as the PR). Merge uses `UseSqlServer("Server=offline", v2022, MicrosoftDataSqlClient)` + `ToSqlQuery` — generation never opens the connection. Temp Table runs `CreateTempTable("FilterIds", ids)` against SQLite in-memory with `UseTracing` capturing `BeforeExecute` SQL, then `ToSqlQuery` on the join; the tab shows SQLite's output (`CREATE TEMPORARY TABLE …`) instead of the PR's hand-written SQL Server `[#FilterIds]` text.
- **rejected:** keep the Temp Table tab manual and say so (igor's fallback) — the review asked for the real path first, and SQLite makes it runnable without a container. Generate Merge on SQL Server for real — needs a container for no gain; `ToSqlQuery` is the documented generation API.
- **why this:** every tab becomes reproducible by one command with no database server.
- **failure mode of the choice:** the Temp Table tab changes dialect from SQL Server to SQLite while the Merge tab stays SQL Server; a reader sees two dialects. Each SQL pane label names its dialect ("Generated SQL · SQLite" / "· SQL Server") so the mix is explicit.

### D-4 — Keep the C# panes as the PR wrote them, regenerate SQL, fix drift on the generator side

- **chosen:** the tab C# is the reviewed content; the generator is edited to match it (drop `Rank`, finalize Merge with the exact chain, real temp table), and each SQL pane is replaced by the regenerated output, re-indented, wrapped in the existing `code-*` spans. Two C# edits are forced by U-5 and stay minimal: Temp Table's `"#FilterIds"` → `"FilterIds"`; nothing else in any C# pane changes. Merge's pane shows the `SET IDENTITY_INSERT` lines and the `CAST(999 AS Decimal(3, 0))` the generator emits (U-4) rather than a trimmed statement. Temp Table's 500-row `VALUES` list is the one elision: shown as `(1), (2), …, (500)` with a `-- 500 rows, abbreviated` comment.
- **rejected:** edit the tabs to match the generator — would change reviewed content and add a `Rank` line nobody asked for.
- **why this:** SC-5/SC-6 then hold by construction and the README's workflow reproduces the page.
- **failure mode of the choice:** the "finalized" Merge cannot call `.Merge()` inside the generator (it executes). The generator stops at the builder the tab finalizes and calls `ToSqlQuery` on it; U-4 must show the text equals what `.Merge()` sends.

### D-5 — Edit links on, scoped by folder

- **chosen:** `globalMetadata._gitContribute = { repo: "https://github.com/linq2db/linq2db", branch: "master" }`, remove global `_disableContribution: true`, `fileMetadata._disableContribution = { "api/**": true }`; landing `index.md` keeps its front-matter `_disableContribution: true`.
- **rejected:** the PR's `api/**/**.yml` glob — covers today's output but not any non-yml file a future metadata entry or template emits.
- **why this:** both reviews; folder scope is file-kind independent.
- **failure mode of the choice:** `branch: master` is hard-coded, so an edit link opened from a page built off a release tag points at master's copy of the file, which can differ. Accepted: docs deploy from releases of master and an edit is always made against master.

### D-6 — Accessible radio group, not ARIA tabs

- **chosen:** keep native radios but hide them visually (clip pattern, still focusable) instead of `display: none`; give `.demo-container` `role="radiogroup"` and `aria-label="Code examples"`; add `:focus-visible` styling that outlines the label of the focused radio (`#demo-tab-N:focus-visible ~ .demo-tabs label[for="demo-tab-N"]`, 7 selectors like the existing `:checked` list).
- **rejected:** `role="tablist/tab/tabpanel"` + `aria-selected` — requires JavaScript to keep `aria-selected` true, which P3 rules out; ARIA without the behaviour is worse than honest radio semantics. A JS tab component — out of scope (P3).
- **why this:** native radios already give arrow-key selection and "n of 7" announcements; the only defect is that `display: none` removed them.
- **failure mode of the choice:** the radiogroup container also wraps the panels, so a screen reader may read panel text as part of the group. Acceptable for a demo; recorded in P10.

### D-7 — Section nav entries link the hub pages

- **chosen:** `topicHref` on the "Documentation" and "Articles" entries of `docs/source/toc.yml`, pointing at `documentation/index.md` / `articles/index.md`.
- **rejected:** leave as the PR wrote it — docfx resolves a folder href to the first relative-file item of the referenced toc (`C:\GitHub\docfx\src\Docfx.Build\TableOfContents\TocResolver.cs:187-195,375-389`), so "Documentation" would land on the first Get Started item (`get-started/install/index.html` at round 1; `get-started/overview.html` after E-14) and "Articles", whose toc holds only an external URL, falls back to `articles/toc.html` (`:260-264`); the hub pages the PR adds would be reachable from the landing cards only (critic round 1).
- **why this:** the hub pages exist to be the section entry points.
- **failure mode of the choice:** the sidebar toc of each section still lists its children only; the hub page is not itself a sidebar item. Accepted, same as the PR's intent.

## Aggregate

GAP-05 ×3, GAP-03 ×2, GAP-02 ×1 and GAP-10 ×1 across the 7 findings, plus GAP-02 and GAP-01 for the two out-of-scope observations. The distribution looks flat by class but not by cause. Three findings (MIN003, MIN004, MIN005) come from one artifact: A-3 narrowed D-1's rule by adding an early return for formats with no items, and had no `re-derives:` line. As a result D-4/D-5's member list, TO-3/TO-4's discriminating input and TO-5's D-3 pin all went stale, along with the G-01 mutation records behind them. Two more (MIN001, SUG001) come from `HandleStringFormat` never getting a `P7` row with a verdict for each branch, even though both D-4 and A-2 changed what it receives. The change that would have prevented the most findings is to enforce a `re-derives:` line on amendments that only narrow or widen a rule, then re-run every control mutation G-01 recorded on the post-amendment tree. The rule was already in the corpus when A-3 was committed; nothing enforces it.

## Recommended durable fixes

- GAP-05/GAP-02 ×3 (MIN003, MIN004, MIN005) → `work-plan.ps1 -Action validate` plus `work-plan.md` → *P11 Amendments* (`:241`). Require a `re-derives:` line on every `A-n` that changes a predicate inside a `D-n`, not only on ones that supersede a decision, add a public type, or add an `E-n` (`work-plan.ps1:419-446` skips A-3 entirely). Add a named shape to the rule: an amendment that adds an early return or short-circuit re-derives every `TO-n` whose discriminating input now takes that branch, and re-runs each mutation G-01 recorded for it on the new tree.
- GAP-03 ×2 (MIN001, SUG001) → the scout brief in `work-plan/SKILL.md` step 5. When a decision changes what a shared helper returns (a new invalid-input result, a newly recognised token), the `P7` row lists each consumer's render branches separately (`BuildFlags`-keyed paths such as `FormatAsExpression` vs concatenation) and gives each branch a verdict. "Callers untouched" is invalid for a contract change. The same applies to an `A-n` that adds a guard inside one of those consumers.
- GAP-05 ×1 (MIN002) → an attack vector in `plan-critic.md`. When a `D-n` states a grammar (EBNF-like item syntax), check that the parser `TO-n` has one invalid input per optional grammar component (trailing junk after the index, an empty alignment, a nested opener), not only for the first component. This applies `work-plan.md:170`, which existed and was not applied by the plan author or by either critic round.

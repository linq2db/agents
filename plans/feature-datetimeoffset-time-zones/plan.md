## P5 Decisions

### D-1 — BLK001: restore the 7-parameter ctor as a defaults-free forwarding shim

- **chosen:** re-add `TranslationProviderFlags(NullsDefaultOrdering, bool, bool, bool, bool, SqlIntervalUnit, bool)` without default values, forwarding with the four zone flags `false` — the shape the 2-parameter ctor already has (`TranslationProviderFlags.cs:15-18`). `PublicAPI.Unshipped.txt` keeps `*REMOVED*` for the shipped line (it carries the defaults) and adds the defaults-free line, as the analyzer requires.
- **rejected:** restore it with its defaults — 5- and 6-argument calls become CS0121 against the 11-parameter ctor (U-16); split the zone flags into a separate type or setters — more public surface for an internal translator input; leave it removed — the binary break BLK001 names.
- **why this:** it is the established compat pattern in the same file, and binary binding is by parameter types, not default values.
- **failure mode of the choice:** the ledger still shows a `*REMOVED*` line for the defaults, which a reviewer may read as the original removal; the thread reply has to say it is the defaults only.

### D-2 — MAJ001: re-attach the offset the source had, through a provider hook

- **chosen:** thread the zoned source out of every site that sets the frame's zone (DFTB:1683, :1695, :1846, :1853, :1873) to `UnframeDateTimeOffset`: the `ConvertZone` node itself (:1856-1880; the conversion `FrameFromZonedOperand` matched at :1695); an `AttachZone(wall, zone)` node built from the matched call for the `DateTime?` overload, whose frame is the wall clock itself (:1683); the `AttachZone` node (:1846); `ConvertZone(value, zone)` for the `ToWallTime` arm (:1853). When the zone is a string and not the constant `'UTC'`, the unframe calls a new `protected virtual ISqlExpression? FromNamedZoneFrame(ITranslationContext, SqlTimeZoneConversionExpression zoned, ISqlExpression framed, DbDataType resultType)`; the base returns null (decline). Overrides:
  - SQL Server 2016 tier (2017/2022 inherit it): `TODATETIMEOFFSET(framed, DATEPART(TZOFFSET, zoned))`. A function node, so the next link reads it through the identity default frame in the carried offset, as .NET does.
  - Oracle: delegates to its own `FromDateTimeOffsetFrame(ctx, zoned, framed, resultType)` — `From_Tz(CAST(framed AS timestamp(7)), To_Char(zoned, 'TZH:TZM'))`, with D-3's cast moved into that shared override.
  - PostgreSQL and DuckDB: `AttachZone(framed, offset)`, where `offset = ToWallTime(src, zone) - ToWallTime(src, 'UTC')` is typed `TimeSpan` (`DataType.Interval`) and `src` is the source instant (a `ConvertZone`'s operand, since neither provider lowers `ConvertZone`; otherwise the `AttachZone` node). The zone is then a fixed offset, so the next link's frame unwraps the node to `framed` (DFTB:1845-1847) — the wall clock in the source's offset, which is what .NET keeps — and its unframe re-attaches the same offset. Their visitors lower an `AttachZone` whose zone is `TimeSpan`-typed as `((value - zone) AT TIME ZONE 'UTC')`. The offset is a provider fragment, `factory.Expression(intervalType, Precedence.Primary, "({0} - {1})", …)`, which neither visitor's interval-difference or binary rewrites touch (`PostgreSQLSqlExpressionConvertVisitor.cs:121-124`, `DuckDBSqlExpressionConvertVisitor.cs:61-68`); its two `ToWallTime` nodes are lowered by the same `LowerTimeZoneConversion`, because a lowered fragment is visited again (`SqlExpressionConvertVisitor.cs:1860-1867`), so a parameter `src` also passes D-13's `TypeParameter` on DuckDB.
  **Checkpoint:** the first implementation step is E-3, E-4, E-5, E-14, E-15, E-23 and E-24 alone, plus TO-2's switch to `IncludeDataSources(true, …)`, with TO-2 and TO-25 run through linq2db on PostgreSQL.16, DuckDB and their `.LinqService` variants — the computed `TimeSpan` zone is the one new shape the serializer carries. If the SQL differs from P-m's shape or answers otherwise, the plan is amended (P11) before any other edit-point.
  A fixed-offset zone and the constant `'UTC'` keep today's `AttachZone`, exact for both. A `'UTC'` held in a parameter or another spelling of UTC goes through the hook, which is correct for it.

## Aggregate

14 findings: GAP-02 ×5, GAP-08 ×3, GAP-03 ×2, GAP-05 ×2, GAP-01 ×1, GAP-06 ×1. There is no GAP-09, because all ten changed files map to E-1…E-10, and no GAP-10. The dominant class has one cause. D-2 and D-3 force on, for every `QueryBatch`, behaviour that #5673 kept opt-in (the combined gate and the Default strategy). The plan measured that forced behaviour only on the three or four combinable, transaction-capable providers its probes ran on. It never asked what the forced path costs or returns where its preconditions fail: non-combinable contexts, providers without transactions, connection-dependent multi-statement support, and the replaced path's Skip emulation and parameter limits (MAJ001, MAJ002, MAJ004, OOS-13, OOS-14). A second cluster of four (MAJ003, MAJ005, MIN001, OOS-11) is one missing grid: overload (arity 1–7, sync and async) × position (root, nested, compiled) × an absolute value oracle. The plan covered only corners of it. G-09's recorded skip is why all 14 reached the PR, but only the three prose rows (MIN002, NIT001, OOS-12) have no earlier artifact to blame.

## Recommended durable fixes

- GAP-02 ×5 (MAJ001, MAJ002, MAJ004, OOS-13, OOS-14) → the scout brief in `work-plan/SKILL.md` step 5, as a new paragraph beside `:142`. When a decision forces an opt-in path, option or strategy on for a new call (a gate bypass, a pinned strategy), that path's divergences go live by default. The plan then owes a P4 probe row for each of:
  - every context in the forced gate's own fallback list (the SC-n that enumerates them), measured for values and command count under each configured alternative the forcing overrides;
  - every provider capability an assertion rests on (transactions, multi-statement per connection string, parameter caps), taken from the flag across all providers rather than from the providers probed;
  - any post-processing or emulation the replaced path applies (`LimitResultEnumerable` for Skip without Take).

  No such shape exists today: a grep of `SKILL.md`, `plan-critic.md`, `work-plan.md` and `testing.md` for opt-in promotion finds nothing. `plan-critic.md:102/:106/:122` cover parts of it after the fact, and round 2 did not apply them, so the scout brief, where probes get scheduled, is the right home.
- GAP-05/GAP-03/GAP-01 ×4 (MAJ003, MAJ005, MIN001, OOS-11) → extend `work-plan/SKILL.md:122` (map every SC/TO per public entry point). For a new `IDataContext` / `IQueryable` extension family, the map becomes a grid: every overload (each arity, sync and async) × every position (root call, node nested in another query's projection, `CompiledQuery.Compile` body). Each cell names the recogniser that admits it and asserts the in-memory expected value. Parity with the API the design reuses (`db.Select`) is not an oracle, because it pins that API's defects (MAJ003). The per-member rules (`work-plan.md:150,:154,:176`) existed and were applied one axis at a time; the grid is what is missing.
- GAP-08 ×3 (MIN002, NIT001, OOS-12) → the G-09 item in `definition-of-done.md` (`:23`). On a Tier M/L plan, G-09 must record `pass` or `waived-by-user: <reason>` before `gh pr create`; `skipped` is not a valid result for it, mirroring P12's `waived-by-user` rule for a skipped critic. Nothing checks this today. `work-plan.ps1 -Action validate -Done` errors only on `(pending)` gates (`work-plan.ps1:395-398`) and runs before G-09 by design, so the check belongs at PR creation, not in `-Done`.

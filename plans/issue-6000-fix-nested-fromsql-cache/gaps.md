## Aggregate

Six of the seven findings come from the A-3/A-4 rewrite: the design was replaced in another author's commits on 2026-10-09 and recorded after the fact on 2026-10-10. For that design, `P4`, `P7` and `P8` were never re-derived, the critic was never dispatched, and `P9` still records gates against the superseded E-1..E-3 diff. In practice the shipped design ran without a plan, under a document that still described the old one. The classes spread (GAP-03 ×2, GAP-05 ×2, GAP-01 ×1, GAP-02 ×1), but they share one root, so this is not a flat set of unrelated misses. The single change that would have prevented the most: treat a design-replacing amendment as a new plan pass that re-opens `P4`/`P7`/`P8` and re-runs the critic. That would plausibly have prevented MAJ001, MIN001, MIN002, MIN003 and MIN004. Only SUG001 is a true floor.

- GAP-03 ×2, GAP-05 ×2, GAP-01 ×1, GAP-02 ×1 (MAJ001, MIN001–MIN005) → `P11` semantics in `work-plan.md` — an amendment that supersedes a `D-n` is not an amendment. Here that means `CompiledQuery.CollectDependentArgumentIndexes`, `CompiledTable<T>`, `DependentArgumentValues`, `ExposeExpressionVisitor.HandleSqlDependentParameters`, and the class summary.
- GAP-05 ×2 (MIN002, plus MAJ001's secondary) → `P8` semantics in `work-plan.md` / `testing.md` — a TO-n for a query-cache fix must assert reuse directly (a miss-count delta or the same `Query<T>` instance), never only `LastQuery`/SQL text. The same SQL can come from a rebuilt query, so a SQL-only assertion cannot go red for a caching regression.

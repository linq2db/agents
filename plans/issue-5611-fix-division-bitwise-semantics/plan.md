## P5 Decisions (M/L; rejected alternatives mandatory at L)

### D-1 — Two capability flags: native unsigned integers, and native unsigned division

- **chosen:** on `SqlExpressionConvertVisitor`, `protected virtual bool HasNativeUnsignedIntegers => false` (`true`: ClickHouse, DuckDB, YDB) gates the unsigned `~` rewrite (D-4); `protected virtual bool DividesUnsignedNatively => HasNativeUnsignedIntegers` (`true` additionally: SQLite, DB2, Firebird — measured green in U-1) gates the `ulong` division default (D-2). MySQL / Access / Oracle / ClickHouse / DuckDB have their own `IntegerDivide` overrides and never reach D-2.
- **rejected:** one flag for both (round-1 draft) — the sets differ: MySQL is non-native for `~uint` (U-4) yet native for `~ulong` (P1 row 5); SQLite / DB2 / Firebird truncate `ulong` division natively (U-1) yet fail `~uint`.
- **rejected:** keying on `MappingSchema.GetDbDataType(typeof(ulong)).DataType` — `UInt64` on providers that render it as `Decimal` (`BasicSqlBuilder.cs:4552`).
- **why this:** each flag is set exactly from a measured provider set.
- **failure mode of the choice:** an external provider inherits the non-native defaults — `FLOOR` on `ulong` division and arithmetic `~` on unsigned — value-correct for any provider whose `ulong` storage is wide enough.

### D-2 — `ulong` division truncates with `FLOOR` where the dialect divides it fractionally

- **chosen:** base `IntegerDivide` returns `Floor(Div(decimal, dividend, divisor))` typed as the result for a `ulong` result when `!DividesUnsignedNatively`; SAP HANA / Informix call `base.IntegerDivide` for `ulong` instead of returning `null`. Operands are non-negative, so floor equals truncation. Reaches: PostgreSQL, SQL Server, Sybase, SqlCe (base), SAP HANA, Informix — the measured red set (U-1).
- **rejected:** `CAST(… AS <integer>)` — no 64-bit unsigned integer type there (bare `Decimal`).
- **rejected:** `Sql.Truncate` spelling per provider — spellings differ; `FLOOR` exists on all 16 (U-2).
- **rejected:** apply everywhere (round-1 draft) — on SQLite it would render `FLOOR(CAST(x AS Float) / y)` (U-17).
- **why this:** one node, applied only where measured red.
- **failure mode of the choice:** Informix's inner `Div` is typed `decimal` here (base), not `double` as its own override builds — so `ulong` quotients stay exact above 2^53 there (reasoned; TO-4 uses small values, P10 notes it).

### D-3 — An integer division over non-integer storage casts the operand to its CLR integer type

- **chosen:** a helper in the base `/` arm, before `IntegerDivide` runs: for an integer division (`IsIntegerDivision`), an operand that is not `ulong` and **contains** a `SqlField` (or a `SqlColumn` resolving to one) whose CLR member type is an integer and whose resolved `DataType` is non-integer numeric storage (`Decimal`, `Money`, `SmallMoney`, `VarNumeric`, `DecFloat`, `Double`, `Single`) is wrapped in a mandatory cast to `MappingSchema.GetDbDataType(<operand CLR type, underlying>)`. The walk does not descend into an existing integer-target cast (`(int)p.MoneyValue`), a predicate / `CASE` condition, or an aggregate argument other than `Sum` / `Min` / `Max` over such a field. Walking covers `X`, `X + 1`, `-X`, `Math.Abs(X)`, `Sum(X)`, dividend and divisor (U-18).
- **not in `TruncateDivide`:** interval components divide `Cast(interval.Value, long)` (`IntervalLowering.cs:286`); the interval fixtures store durations as `DataType.Money` under `Wide` (`IntervalTranslationTests.cs:41-57`, `…Members.cs:31,36,151,156`), where a fractional amount cast before dividing could round on PostgreSQL (3599.6 s → 1 h) — out of D-3's scope, P10 (round 2).
- **rejected:** a node-type test (`QueryHelper.GetDbDataType(operand)`, round-1 draft) — misses every composite operand (U-18).
- **rejected:** only on the `null` path — DuckDB (`//` on DECIMAL) and YDB are red (U-3).
- **rejected:** truncate the quotient (`TRUNC(x / 2)`) — per-provider spelling.
- **why this:** the operand's CLR type is an integer, so C# semantics are integer; the cast makes the server agree for every provider, override or not. An integer-valued decimal casts exactly everywhere.
- **failure mode of the choice:** an `int` member over a column holding a fraction is cast (SQL Server truncates, PostgreSQL rounds) before dividing — outside the mapping contract; P10. Override providers that were already correct (Oracle, Access, SAP HANA, Informix, MySQL, Firebird, SQLite) gain one cast — value-neutral for integer-valued storage; baselines move only for tests dividing over non-integer storage (shared models have none, scout 1/4).

### D-4 — Unsigned `~` is rewritten as a bracketed subtraction from the type's maximum, before the provider dispatch

- **chosen:** in `SqlExpressionConvertVisitor.VisitSqlUnaryExpression`, before it dispatches to `ConvertSqlUnaryExpression` (so before every provider override — MySQL, SAP HANA, ClickHouse, Access, Oracle, Informix, DB2, Firebird, YDB), a `BitwiseNegation` whose `SystemType` (underlying) is `uint` or `ulong` — keyed on the **result only**, because a provider may already have elided the operand's integer cast (Access `ConvertConversion`, `AccessSqlExpressionConvertVisitor.cs:502-519`; probe log `…-23584-173415452.log:8,167` shows `-1 - [p].[ID]`) — is rewritten unless `IsNativeUnsigned(<unsigned type>)`. Output: `SqlExpression` template `"({0} - {1})"` at `Precedence.Primary`, `ParametersNullabilityType.IfAnyParameterNullable`, over `4294967295` / `18446744073709551615` and the operand; for `uint` wrapped in a mandatory cast to `MappingSchema.GetDbDataType(<underlying type>)` (an enum node's own type may resolve `Undefined`, `MappingSchema.cs:1659-1669`, which a cast target rejects, `BasicSqlBuilder.cs:4532-4534`; precedent MySQL `AsSigned` `:39`, YDB `:210,222`), then `.WithSystemType(<node SystemType>)`.
